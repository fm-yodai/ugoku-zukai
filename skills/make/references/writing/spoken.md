# 聞いて分かる文の規則（SP-）

字幕とナレーションは、画面を見ながら一度だけ聞く文である。読み返せないので、聞いた順に意味が取れることを見る。正確さは `rules.md`（TW-）が見る。指摘は `SP-<番号>` で規則を指す。

| # | 規則 | 悪い例 | 直した例 |
|---|------|--------|---------|
| SP-1 | **冒頭の 1 行目で、何の説明かを素直に言う。** 問いで始めるのは、視聴者の言葉で立てられ、答えが動画の中にある問いのときだけ | 「題材を渡すと、何が起きて再生ページになるのでしょうか」 | 「動画作成プラグイン ugoku-zukai について説明します」 |
| SP-2 | **視聴者の前提にない語は使わない。** 使うなら意味を先に、別の文で言う。名詞の前に説明を重ねない | 「進行役がチャットでページを公開する仕組み Artifact に載せ、共有します」 | 「Artifact は、チャットの中でページを公開する仕組みです。進行役はここに再生ページを載せます」 |
| SP-3 | **スキルや題材の内部の呼び名は、視聴者が知る必要があるときだけ、意味を言ってから使う。** 知らなくても分かるなら出さない | 「{a}作り手の researcher が答えを読み、言い切ることと根拠を並べた契約を書きます。」 | 「{a}答えをもとに、動画で言うことの一覧を書きます。」 |
| SP-4 | **1 文に 1 つのこと。** 50 字以内を目安にし、並べるのは 3 つまで。4 つ以上は文を分けるか、まとめる言葉で束ねる | 「{a}聞くのは読者・一番分かってほしいこと・範囲・構成の型・長さ・声・画風と、音声合成 VOICEVOX の利用規約への同意です。」 | 「{a}聞くのは、誰に見せるか、何を分かってほしいか、どこまで扱うかです。長さと声も、ここで決めます。」 |
| SP-5 | **印 `{a}` のために読点を増やさない。** 節の切れ目の読点はそのまま残す | 「{a}作り手と、{b}評価役は、別の担当です」 | 「{a}作り手と{b}評価役は、別の担当です」 |
| SP-6 | **「の」を 1 文に 3 つ以上続けない。** 続けて 3 つ出たら、語を言い換えるか文を分ける | 「進行役は {a}判定を台帳に取り込み、{b}台帳を扱う ledger.py の status の結果で次を決めます。」 | 「進行役は {a}判定の結果を記録し、{b}記録の集計を見て次を決めます。」 |
| SP-7 | **比喩・演出・造語をしない。** 同僚に口頭で説明するときの言葉を物差しにする | 「地図だよ。」「1 つ目の目玉なのだ」 | 「全体の構成を示す図です。」「1 つ目の注目点なのだ」 |
| SP-8 | **名詞と動詞の組み合わせを確かめる。** 声に出して、その動詞を普通その名詞に使うかを見る | 「判定を台帳に取り込み」「契約を書きます」 | 「結果を記録し」「一覧を書きます」 |
| SP-9 | **直しすぎない。幼くしない。** 定着した用語（シーケンス図・API・キャッシュなど）を和訳しない。やさしくするために内容を削らない | Artifact を「成果物」と訳す。JSON を「ジェイソン形式のデータ」と書く | 「Artifact」「JSON」のまま使う。視聴者が知らなさそうなら、初出で 1 文だけ意味を言う |

writer は書く前に読み、書いた後に SP-1〜SP-9 を 1 つずつ見直す。writing-reviewer は `interview.md` の視聴者として初めて聞いたつもりで S-W5〜S-W7 を判定する。
