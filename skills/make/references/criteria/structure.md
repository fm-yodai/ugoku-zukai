# スライドと図の基準（G-）

対象は、台本（`storyboard.json`）のスライドの宣言（`slides` の見出し `title`・言いたいこと `statement`・部品 `parts`・区画 `area`）、部品として置いた図（`figures` と、スライドの中で宣言した図）、それを動かす動作（`do`）である。最初のスライドコンテを見せる前に判定し（`target` は `script`）、G-D5 と G-D8 は行ごとのコマでも見る（`target` は `screen`）。形式は `../storyboard.md` の 8 章（スライド）と 2 章（図の種類）が正。

スライドは、声と字幕がなくても資料として読める 1 枚である。評価役は、**スライドの完成形**を見る。完成形は、途中で消える部品（`transient`）を除いて、宣言した部品がすべて出た状態を指す。`frames.cjs` が、スライドごとに完成形のコマ（`frames/svg/slide-<スライドの id>.svg`。`frames.json` の `slides` に、id・ファイル・使う場面）を書く。

配置はプレーヤー（区画、ELK、図ごとの固定配置）が決めるので、座標の良し悪しは機械検査に任せ、評価役は**意味の構造**を見る。記法の項目は C4 モデルの記法チェックリスト（https://c4model.com/diagrams/notation）に倣う。

スライドの意図に照らす基準（G-D11〜G-D13）では、`evidence` に、照らした意図の場所と文の引用を書く。スライドが意図どおりの 1 枚かどうかそのものは、`agreement.md` の A-3 で見る。

| G-D4 | 行きと戻りが矢印の向きで読める（VG-7）。1 本の辺で行きと戻りを兼ね、どちら向きの話かが線から読めないのは FAIL。応答を描くなら別の矢印（`reply` の動作、`sequence` のメッセージの `reply: true`）。戻りが話の中心でない図で、戻りを描かないのは合格 | director | should |
| G-D5 | 色の役割（`role`・`tint` の `as`）の意味がスライドをまたいで一貫し、凡例で説明できる（VG-2。正常な応答を「消えた・失敗」の `removed`・`bad` で描かない） | director（スライドとコマ） | should |
| G-D6 | 区分の分け方が実際の配置・責務の境界に合っている。`graph` の `groups`（`band` の層・`frame` の囲み）、`swimlane` の担当、`sequence` の参加者が、クライアント / 入口 / アプリケーション / 認証基盤 / データ 等の境界（概念の図なら要素の分類の境界）で切られている。層を宣言した `graph` では、各ノードがちょうど 1 つの層に入っている | director | should |
| G-D7 | スライドに見出し（`title`）があり、資料の見出しとして読める。見出しだけを読んで、何についての 1 枚かが分かる。見出しは、字幕の言い回しに合わせて書くものではない。字幕の問いかけや話し言葉の文をそのまま写した見出し（「では、UX とは何でしょうか」）は、資料の見出しになっていない。章扉（`title` の図だけの場面）の題も、同じに見る。前の形式の場面（`figure` を指す場面）では、場面の `title` か図の `title` を見る | director | must（見出しがない、または何についての 1 枚かが分からない）/ should（分かるが、字幕の言い回しを写している） |
| G-D8 | 画面で、辺が無関係の箱を貫かず、点の札が箱の名前の文字を隠していない（配置の検査は辺の線と点を見ない。点は辺の上を動く間だけ見え、箱にいる間は箱の枠が強調される） | director（コマ） | should |
| G-D9 | 1 つの図が、同じことを 2 度言っていない。表の隣り合う列や、比較・As-Is/To-Be の左右が、言葉を変えて同じ内容を並べているだけなら、列を 1 つにするか、図の種類を変える | director | should |
| G-D10 | 表の形の図で、箱の形が情報を持っている。`roadmap` や `swimlane` の箱は、期間の長さや受け渡しの順を見せる所で効く。行と列に言葉を置くだけの内容を、セルの中に箱を並べて描き、箱の形が何も伝えていないのは FAIL（`table` なら言葉だけで読める） | director | should |
| G-D11 | スライドに言いたいこと（`statement`）があり、この 1 枚で伝えたいことを 1 文で言い切っている。見出しを言い直しただけの文、「〜について」で終わる文、字幕の 1 行をそのまま写した話し言葉の文は FAIL。言いたいことのないスライドは、なくてよい理由がスライドの意図から読めれば合格（意図が「図ひとつで関係が分かる」で、図だけで足りる。章扉である、など）。理由が意図から読めなければ FAIL | director | must |
| G-D12 | スライドが、声と字幕がなくても資料として読める。字幕を読む前に、完成形（見出し・言いたいこと・部品）だけを見て、この 1 枚が何を言っているかを 1〜2 文で書き出せる（`evidence` に残す）。書き出せない、または、字幕を聞かないと部品の意味や部品どうしの関係が分からない（名前のない箱が並ぶ、図に何の図かを示す言葉がない、文の途中だけが置いてある）なら FAIL。書き出した内容が意図と合うかは A-3 で見る | director | must |
| G-D13 | 1 枚で 1 つのことを言っている。言いたいことが 2 つのことを言っている、部品が別々の話をしている、スライドの意図が 2 つのことを分かることを求めていて 1 枚に詰めてある、のどれかなら FAIL。`suggestion` に、どこで分けるかを書く（スライドの切り方を変える案は、進行役が案を並べて利用者に選んでもらう） | director | must（別の話が混ざり、何の 1 枚かが分からない）/ should（1 つの話だが、2 枚に分けたほうが読みやすい） |
| G-D14 | テキストの量が、読み切れる量である。聴衆は、原稿を聞きながらスライドを読む。完成形のテキスト（見出し・言いたいこと・テキストの部品・図の中の文字）を、そのスライドが出ている間（使う場面の行の長さ。`frames.json` の行の時刻で分かる）に読み切れるかを見る。段落が並んで文章の資料になっている、字幕と同じ長さの文が箇条に並んでいる、は多すぎる | director | must（読み切る前に次のスライドへ移り、読めないまま進む）/ should（読み切れるが、削ったほうが言いたいことが目に入る） |
| G-D15 | 図と文章が、同じことを 2 度言っていない。図の中の名前とラベルで言えていることを、隣のテキストが言葉を変えて繰り返しているだけなら FAIL。テキストは、図から読み取れないこと（定義、理由、条件、出どころ）を言う。言いたいこと（`statement`）が図の結論を 1 文で言うのは、繰り返しに数えない | director | should |
| G-D16 | スライドの見た目が、デザインの原則（`references/layout.md`。近接・整列・反復・対比、余白、声と一緒に見せる原則）に照らして、聴衆が読みやすい。完成形の PNG を見て、空きが部品の間に半端に挟まっている、量が片側に偏っている、文章が複数行なのに中央揃え、関係の強い部品が離れている、などで読みにくければ FAIL。原則は決まりではないので、利用者が指定した見た目や、意図から読める理由があれば PASS。`evidence` に、どの原則に照らしたかを書く | director | should |
| G-D17 | **キャンバスが育つ（Morph。VG-10）**: 続くスライドを `morph` でつないだこと、つながなかったことが、章とスライドの意図に対して効いている。つないだ 2 枚は完成形のコマを 2 枚並べ、同じものの続きに読めるかを見る（共通の要素が同じ並びと同じ名前で残り、増えた・変わった所だけが違う。`graph` の系列では、同じ箱の画面上の位置と大きさは 2 枚で違ってよい）。中身の違う 2 枚が同じものに見える、どの切り替えも動いて合図にならない、は使いすぎ。意図が「同じものの続き」を分かってほしいのに、聴衆が別々の 2 枚を見比べて違いを探すことになるのは、効く所を逃している | director | should |
| G-D18 | **カメラ（`zoom`・`pan`。VG-11）**: 寄る・引く・移る動きが、その行と意図に対して効いている（話している所に注意が集まる、全体のどこかの見当がつく）。せわしない、寄ったまま話が移って迷子になる、十分読める図で寄って動きが飾りになる、は使いすぎ。意図が全体の中の一部を読ませたい・位置づけを分からせたいのに、小さいまま、または全体との関係が見えないまま進むのは、効く所を逃している | director | should |
| G-D19 | **線の描画（`draw`。VG-12）**: 線を描きながら出すことが、経路や囲みの範囲に注意を向けたい所で効いている。経路の話でない所まで線から描いて遅くなる、どれも描いて動きが情報を持たない、は使いすぎ。経路そのものが意図の中心なのに線がただ現れるのは、効く所を逃していることがある（普通の `show` で伝わるなら合格） | director | should |
| G-D20 | **値の連動（`values`・`set`・`custom` の部品。VG-13）**: 値を動かして図と数をついてこさせたこと、動かさなかったことが、章とスライドの意図に対して効いている。宣言（`values`・`set`・`custom` の関数）と、行ごとのコマ（値の途中と動かし終えた姿）から、何が変わり何が変わらないかを聴衆が目で追えるかを見る。いくつもの値を同時に動かして見る所が分からない、動いている所と話していることがずれる、値を動かしても関係が変わらず動きが飾りになる、は使いすぎ。意図が「値と結果の関係」や「変わり方」を分かってほしいのに、止まった図を何枚も見比べさせる、数を言葉だけで並べる、のは効く所を逃している | director | should |
| G-D21 | **数式の変形（`geo.texMorph`。VG-14）**: 式を変形で見せたこと、見せなかったことが、意図に対して効いている。前後の式と印（`\cssId`）の付け方から、どの項がどこへ行ったかを聴衆が追えるかを見る。動く部分が多すぎて途中が文字の重なりになる、結果だけ分かればよい式まで変形する、印がなく項がその場で入れ替わるだけで動きが情報を持たない、は使いすぎ。意図が「変形の前後が同じもの」「項がどこから来たか」を分かってほしいのに、前と後の式を別々に出すだけなのは、効く所を逃している | director | should |
| G-D22 | **奥行き（`space` の部品・板 `plate`・`inside`。VG-15〜VG-17）**: 立体を回して見せたこと、層を起こしたこと、箱の中に入ったこと、平らなまま見せたことが、章とスライドの意図に対して効いている。完成形のコマと行ごとのコマで、止まった向きから、言いたいこと（`statement`）の関係が読み取れるかを見る（言いたい所が裏に回って隠れていない、ほかの要素と重なって読めない向きで止まっていない）。回しても形の手がかりが増えない、立体である必要のない関係を立体で描いて平面より読みにくい、起こした板の文字がつぶれて読めない、中に入ったまま今どの段にいるか分からなくなる、は使いすぎ。意図が形・層の重なり・箱の中身を分かってほしいのに、1 つの向きの平らな図だけで見せる、全体と中身を関係の見えない別々の図にする、のは効く所を逃している | director | should |

指摘の場所（`where`）は、スライドとその部品への指摘なら、そのスライドを最初に使う場面の id（`s3`）にし、`problem` の頭にスライドの id（部品への指摘なら部品の id も）を書く。`figures` に宣言した図への指摘は、図の id でもよい（`../writing/review-format.md`）。

スライドの指摘は、スライドの宣言と動作で直す。原稿（字幕）は、スライドに合わせて後から直す。スライドを字幕に合わせて直さない。

## 較正の例

- **全体像が構造的でない**（過去の指摘「整理されているようでそこまで構造的に整理されていない」）: 箱が格子に並ぶだけで層の区切り（`groups` の `band`）が無く、認証基盤が公開する鍵（JWKS）が、認証基盤の枠の中ではなく独立した箱になっていた → G-D6
- **点が中途半端な場所に止まる**（過去の指摘。今は、点は箱にいる間は出ず、箱の枠が強調される）: 点が箱の名前の文字の上に止まる → G-D8
- **左右の列が同じことを言う表**（利用者の指摘）: 「お客様の言葉」と「当てはまるケース」を左右に並べた表で、両方の列が同じ内容を言い方を変えて書いていた → G-D9
- **表のセルに箱を並べた**（利用者の指摘「うるさい」）: 段階ごとの成果物を `roadmap` の箱で並べ、表の中に箱が詰まった。セルの中が言葉だけなら `table` にする → G-D10
- **応答が赤**（過去の画面レビュー）: 認証基盤からの認可コード・アクセストークンの戻り矢印が赤（`bad`）で、失敗に見えた → G-D5
- **図の種類を選ばずに全部を 1 枚の箱と矢印に詰めた**（過去の指摘）: ログインの往復（誰が誰に何を渡すか）を構成図（`graph`）の上の点の移動だけで見せ、順序が追えなかった。往復が主題なら `sequence` を選ぶ → G-D2
- **見出しと図の題が、字幕をなぞった**（利用者の指摘「絵はスライド資料のように作る」）: 章扉が字幕の問いをそのまま写し、図の題も字幕の言い回しに合わせてあった。見出しは資料の見出しとして書く → G-D7
- **概念図だけの 1 枚が続いた**（利用者の指摘）: どの画面も図が 1 つあるだけで、その 1 枚で何を言いたいのかが画面に書かれていなかった。実際の資料では、上に「この 1 枚で伝えたいこと」があり、その下に素材とテキストが組み合わさっている → G-D11（図だけで何の話かが分からなければ G-D12）
- **同じ構成図が、別々の 2 枚に見えた**（想定の例）: キャッシュを足す前と後の構成を独立した 2 つの `graph` で描き、箱の並びが入れ替わって、どこが増えたかを見比べないと分からなかった。後の 1 枚の部品に `morph` を書き、ノードの id をそろえる → G-D17
- **傾きの数を言葉だけで並べた**（想定の例）: 曲線の 3 か所の接線を別々の 3 枚で描き、傾きの数を字幕で読み上げた。聴衆は 3 枚を見比べて、傾きが点とともに変わることを自分で組み立てることになった。点の位置を値にして `set` で動かし、接線と傾きの数を値から描く → G-D20
