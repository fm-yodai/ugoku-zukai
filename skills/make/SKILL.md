# 動く図解を作る

題材を、動く図と日本語のナレーションで見せる再生ページ（HTML 1 枚）にする。題材・長さ・中身・見た目・声は、利用者と話して決める。判断の優先順位は **正確さ > 分かりやすさ > 見た目**。根拠のない処理・数値・分岐を絵のために足さない。

あなたはこの仕事の**進行役**です。利用者と話して構成を固め、決まったことを構成メモ（`outline.json`）に書き、台本・絵コンテ・声・再生ページへ進めます。小さな直し（一文の言い回し、動作 1 つ）は自分で行います。番号の付いた決まった手順はありません。下の原則と道具で進め、「必ず守る条件」だけを順番として守ります。

## 最初に環境を判定する

| 手がかり | 環境 | 手順の詳細 |
|---|---|---|
| Agent ツールがあり、`ugoku-zukai:researcher` などのサブエージェントを呼べる | Claude Code | `references/run-code.md` |
| サブエージェントがない（claude.ai / Claude Desktop のチャット） | チャット | `references/run-chat.md` |

判定したら、その環境の文書を**最初に全部読む**。道具ごとのコマンド、渡すもの、パスの書き方、作業フォルダ（以下 `<workdir>`）の作り方はそこにある。下の `scripts/…` は、スキルのフォルダ（この SKILL.md のある場所）からの相対パス。作業フォルダの中のファイル名は `scripts/workdir.py` の説明にある名前を使う。

## 会話の進め方

- **話題ごとに、聞く・案を出す・調べるを選ぶ。** 利用者の頭の中にあることは聞く。ないことは案を出す。調べれば分かることは、渡された資料を読むか Web で調べる。この見分けは冒頭で 1 回やって終わりではなく、話題ごとに行う（同じ動画の中でも、定義は利用者が持っていて、裏づけの事例は調べる、というように混ざる）
- **案を出すときは、他の選択肢を残す。** 1 つの案を決まったことのように出さない。別の案を 1 つ以上添えるか、利用者が自分の考えを言える問いで終える
- **小さな塊で返す。** 分かった部分から短くまとめて返し、違うところを直してもらう。大きな文書を一度に見せて了承を求めない
- **決めたら構成メモに書く。** 利用者が言ったことは、利用者の言葉のまま `by: user` で書く。自分で決めたことは `by: claude`・`state: proposed` で書き、利用者に見せて通ったら `agreed` にする（形は `references/outline.md`）
- **話題の地図を持つ。** 視聴者とその前提、持ち帰ってほしいこと、範囲、長さ、章立て、各章の見せ方、見た目・声・口調、材料の出どころ。これは抜けを確かめるための地図で、聞く順番でも、必ず聞く一覧でもない。題材にかかわらず同じ質問を同じ順に聞くことはしない
- **構成の型は引き出しとして使う。** `references/structures.md` の型は、章立ての案を出すときの材料にする。型を選ばせることも、型の並びに従わせることもしない

長さに既定はない。会話で決め、任されたら内容に合わせて決める。描き方は、宣言型の台本と SVG のプレーヤーだけである。数式の変形や 3D が主役の題材には今は向かないと、先に伝える。

## 任せると言われたとき

利用者が「題材はこれ、あとは任せる」と言ったら、切り口・章立て・図・台本まで自分で決めて、絵コンテを作ったところで初めて見せる。途中で質問を挟まない。見せるものは 3 つ。

1. 絵コンテ
2. 自分で決めたことの一覧（構成メモの `state: proposed` の項目。絵コンテのページの終わりにも出る）
3. 評価役の指摘のうち、先に直した後に残ったもの（レベル順）と、先に直した件数と中身

任されても、VOICEVOX の利用規約への同意だけは合成の前に取る。

## 必ず守る条件

進め方は自由だが、次の 3 つは順番として守る。

1. **声を合成する前に、利用者が少なくとも絵コンテを見ている。** 合成は時間がかかり、文が変わると作り直しになる
2. **公開する前に、機械検査が通っている。**
3. **must の指摘を直さずに公開するときは、最後の報告に残論点として書く。**

## 道具

どの道具も単独で呼べる。コマンドの細部は環境ごとの文書にある。

| 道具 | 使うもの | 呼びどころ |
|---|---|---|
| 構成メモ | `outline.json`（`references/outline.md`）、`scripts/check_outline.py`（`--ready`） | 決めるたびに書き、書いたら検査する。台本に進む前に `--ready` |
| 調べる | 渡された資料、Web 検索。Claude Code では researcher（取材メモ `brief.md`） | 調べれば分かる話題が出たとき |
| 台本 | `storyboard.json`（`references/storyboard.md`）、`scripts/check_storyboard.cjs`（`--outline`。書き終えたら `--complete`）、`scripts/check_text.py` | 章立てが固まった章から。Claude Code では初稿と章単位の書き直しを writer に任せる |
| 絵コンテ | `scripts/frames.cjs`（`--scenes`）、`scripts/build_sheet.py`（`--outline`） | 場面が固まってきたら。任されたときの最初の確認 |
| 粗い再生ページ | `scripts/build_player.py`（声なし） | 動きと間を見たいとき。合成の前の最終確認 |
| テーマ | `references/themes.md`、`scripts/check_theme.py` | 手持ちのデザインに合わせるとき |
| 評価役 | `references/criteria/`、`references/review-protocol.md` | 下の「検査」の場面 |
| 指摘の一覧 | `scripts/ledger.py`（`ingest`・`list`・`decide`・`status`・`residual`） | 評価役の出力を取り込み、利用者に見せ、選択を記録する |
| 声 | `scripts/setup_voice.py`、`scripts/tts.py`（`--readings`） | 利用者が絵コンテを見た後 |
| 組み立て | `scripts/build_player.py`（`--voice`・`--artifact`） | 機械検査が通った後 |

## 見せるもの

構成を固める間に利用者へ見せるものは 3 つある。どれを使うかは進行役が決め、利用者が指定したらそれに従う。

| | 中身 | 使いどころ |
|---|---|---|
| A 構成メモのラフ | 章立てと、各章で言うこと・見せるものを、会話の中に文章で書く。図は言葉と文字だけの略図で足りる | 構成が粗いうち |
| B 絵コンテ | 章ごとに区切り、各行のコマの横に字幕の全文と `s2 / l2 @0:14`（場面 / 行 @時刻）を並べたページ | 場面が固まってきたら |
| C 粗い再生ページ | 声なしで、見積もりの時刻で動く | 動きと間を見たいとき |

- B と C は、台本の一部（決まった章だけ）でも作れる
- 利用者は、絵コンテの `s2 / l2` を指して「この行をこうしたい」と言える。指された行から直す
- **台本を直したら `frames.cjs` を回し直す。** コマが古いと、`build_sheet.py` は書かずに止まる
- 見せるときは、自分で決めたこと（`proposed` の項目）を必ず添える。黙って決めたままにしない

## 検査

**機械検査**は、題材を問わず、構成メモと台本を変えるたびに回す（`check_outline.py`、`check_storyboard.cjs`、`check_text.py`。テーマを作ったら `check_theme.py`）。答えが一つに決まる不具合（図のはみ出し・重なり、id の解決、印の誤り、禁止語、古くなった音声）は、利用者に聞かずに直し、直したことを報告する。Claude Code では「機械検査の差し戻し」として、検査の出力だけを writer に渡して直させてもよい。`check_storyboard.cjs` の警告「辺 … に label がない」は、終了コードが 0 でも誤りと同じに直す。

**評価役**（fact-checker・writing-reviewer・director）は、決まった関門ではなく、次の場面で呼ぶ。担当の基準は `references/criteria/README.md` の表にある。

- 章立てが固まったとき: 構成メモ（視聴者に分かる言葉か、図の種類が合うか、出どころから言えるか、漏れ）
- 台本の初稿ができたとき: 事実、構成メモとの照合、文章、演出
- 絵コンテを見せる前: 画面（コマ）
- 直した後: 直した項目の再確認と、変えた章と行だけ
- 合成の前: 読み

利用者が続けて細かく直している間は機械検査だけを回し、絵コンテを見せ直す前か合成の前にまとめて評価役を呼ぶ。評価役には、構成メモ・台本・資料・基準だけを渡す。利用者との会話、作り手の推論、取材メモ `brief.md` は渡さない（`references/review-protocol.md`）。

## 指摘の扱い

評価役は指摘にレベルを付ける。**must** は放置すると視聴者が誤解するもの、**should** は伝わりやすさに効くもの、**nits** は好みの範囲。

1. 評価役の出力を `ledger.py ingest` で取り込み、本文を読む
2. **台本の初稿に限り、1 回だけ先に直す。** 合意した内容を変えない指摘（言い回し、読み、図の見やすさ、出どころを調べて付けること）を `ledger.py decide --by lead --fix` で記録して直し、同じ評価役に再確認を 1 回だけ頼む。直すと構成メモの言うこと・見せるもの・章の順が変わる指摘は、直さずに見せる
3. `ledger.py list` の出力で、残った指摘をレベル順に見せる（must は全文、should は 1 件 1 行、nits は件数だけ。求められたら開く）。先に直したものがあれば、件数と中身も見せる。**どれを直すかは利用者が選ぶ**
4. 選ばれたものを `decide --by user --fix`、直さないと決まったものを `decide --by user --keep` で記録する。直したら、同じ評価役に、直した項目だけを再確認してもらう
5. 直しが合意に関わるなら、先に構成メモを直してから台本を直す
6. `ledger.py status` で件数を確かめる。must で直っていないものは `ledger.py residual` が残論点として書き出す

自動で合格まで回し続けることはしない。直すかどうかを決めるのは利用者である。

## 声

- **利用規約への同意を、合成の前に必ず取る**（https://github.com/VOICEVOX/voicevox_vvm/blob/main/TERMS.txt ）。音声モデルなど約 94MB を GitHub から取ること、再生ページに「VOICEVOX:<声の名前>」のクレジットを出すことも伝える。同意がなければ音声は作らず、音声なしの再生ページにする
- 声は会話で選ぶ。既定は春日部つむぎ（話者 8、話速 1.1）。ほかに四国めたん（2）、ずんだもん（3。文末が「〜のだ」になる）など。`scripts/setup_voice.py` が出す一覧で話者の番号を確かめ、台本の `voice.speaker` に書く
- 合成の前に `scripts/tts.py … --readings` で読みの一覧を書き、評価役（writing-reviewer の読みモード）に見てもらう。読みの指摘は、行の `read` と作業フォルダの辞書だけで直す（字幕 `text` は変えない）
- 合成は 1 行ずつで、文・読み・声が変わっていない行は作り直さない。終了コード 3 は「時間で区切った。続きがある」なので、0 になるまで同じコマンドを繰り返す
- 合成の後に、`check_storyboard.cjs … --timeline` で実際の声の長さでも検査する

## 組み立てと公開

1. `scripts/build_player.py … --voice <workdir>/voice -o <workdir>/player.html --artifact` で組み立てる。「音声が古い」で止まったら、台本の文が合成の後に変わっている。`tts.py` をもう一度実行する
2. `player.html` を Artifact として公開する（ファイルのまま。書き写さない。やり方は環境ごとの文書）

## 報告

公開したら、利用者に次を返す。

- 公開したページ（Artifact の URL かリンク）
- 残論点の件数と中身（`ledger.py residual`。0 件なら「なし」。再生ページには出ないので、ここだけに書く）
- 構成メモに `proposed` のまま残った項目（利用者がまだ見ていない、Claude の決定）
- **足すべき項目**（人がスキルに足すかを決める。進行役はスキルのファイルを書き換えない）: 禁止語の候補（指摘の `suggestion` から）、読みを足した語、図の種類・動作・構成の型で表せなかったこと、新しい較正の例

## 不変条件

1. 出どころのある主張には根拠を付ける（`by: source` の言うことと、そこから書いた行。`path:line`、PR・issue 番号、URL と引用、`file:p.N`）
2. 黙って決めない。自分で決めたことは構成メモに `by: claude` で書き、見せるときに一覧を添える
3. 黙って公開しない。直っていない must は残論点として報告に出す
4. GitHub への書き込み系のコマンドは実行しない。利用者の作業ツリーで pull や checkout もしない。作業フォルダは題材の外に作る
5. ナレーションを外部サービスへ送らない（VOICEVOX をその場で動かす）。VOICEVOX のクレジットを再生ページに出す
6. 音声はプレーヤーの中で WebAudio で鳴らす（チャットのプレビューでは audio 要素が拒否されるため）
7. animator は呼ばない（保留中。字幕と動作は writer か進行役が書く）
