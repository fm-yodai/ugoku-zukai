# 構成メモの形式（ugoku-zukai-outline/2）

構成メモ `<workdir>/outline.json` は、動画について利用者と合意したことの記録である。聴衆、持ち帰ってほしいこと、長さ、見た目、声と、3 段の意図（章の順番の意図、章の意図と章のつながり、スライドの意図とスライドのつながり）を、独立に直せる項目の集まりとして持つ。スライドと原稿はこの意図を元に作り、評価役は「意図どおりのスライド・原稿になっているか」を見る。

書いたら検査する:

```bash
python3 scripts/check_outline.py <workdir>              # 形・id の重複・根拠の有無
python3 scripts/check_outline.py <workdir> --ready      # 台本に進める状態かも見る
python3 scripts/check_outline.py <workdir> --json       # 結果と、まだ確認していない項目の一覧を JSON で出す
```

## 例

```json
{
  "format": "ugoku-zukai-outline/2",
  "title": "ユーザビリティと UX の違い",
  "basics": {
    "audience": { "text": "自社の開発部", "by": "user", "state": "agreed" },
    "knows":    { "text": "UI/UX という言葉は聞いたことがある。二つの違いは説明できない", "by": "claude", "state": "proposed" },
    "takeaway": { "text": "ユーザビリティは UX の一部で、UX は使う前から使った後までの体験の全体を指す", "by": "user", "state": "agreed" },
    "length":   { "text": "40 秒くらい", "seconds": 40, "by": "user", "state": "agreed" },
    "look":     { "text": "空 提案書デザイン（既定）", "theme": "koo", "by": "claude", "state": "proposed" },
    "voice":    { "text": "落ち着いた声", "speaker": 8, "speed": 1.1, "by": "claude", "state": "proposed" },
    "tone":     { "text": "です・ます。一般的なビジネスの語り口", "by": "user", "state": "agreed" }
  },
  "flow": { "text": "聞いたことのある二つの語の関係を先に見せ、次に定義で裏づけ、最後に誰の体験かに戻す。聴衆が、知っている語から順に整理できる",
            "by": "claude", "state": "agreed" },
  "chapters": [
    { "id": "c1", "title": "二つの言葉の関係", "seconds": 13,
      "intent": { "text": "ここで聴衆は、UX がユーザビリティを含む、より広い語だと分かる", "by": "user", "state": "agreed" },
      "slides": [
        { "id": "relation",
          "intent": { "text": "二つの語の包含関係が、図ひとつで分かる", "by": "claude", "state": "proposed" } } ] },
    { "id": "c2", "title": "二つの言葉の定義", "seconds": 28,
      "intent": { "text": "ここで聴衆は、二つの語が規格でどう定められているかを読み、UX の範囲が使う前から使った後までだと分かる", "by": "claude", "state": "agreed" },
      "link":   { "text": "関係が分かったので、それぞれが何を指すかを規格の言葉で押さえる", "by": "claude", "state": "agreed" },
      "slides": [
        { "id": "definitions",
          "intent": { "text": "二つの定義を並べて読み比べ、見ているものの違い（度合いと、知覚と反応）に気づく", "by": "claude", "state": "proposed" } },
        { "id": "ux-def",
          "intent": { "text": "UX の定義の文そのものを読み、範囲が使う前・使っている間・使った後に及ぶと分かる", "by": "claude", "state": "proposed" },
          "link":   { "text": "二つを比べた後で、広いほうの UX を詳しく見る", "by": "claude", "state": "proposed" } } ] }
  ],
  "open": [ "規格の番号をスライドに出すか" ]
}
```

通る見本は `examples/outlines/` にある（`slide-forms.json` は見本台本 `examples/slide-forms.json` と対になる。`ux.json` は題目と利用者の考えから作る動画、`keihi.json` は提案の動画）。

## 3 段の意図

| 段 | 場所 | 書くこと | 決めるとき |
|---|---|---|---|
| 章の順番の意図 | `flow` | なぜこの順に章を並べるか。全体に 1 つ | スライドを作る前に、会話で決める |
| 章の意図 | `chapters[].intent` | この章で聴衆が何を分かるか | スライドを作る前に、会話で決める |
| 章のつながり | `chapters[].link` | 前の章から、なぜこの章に進むか（任意。最初の章には書かない） | 章の意図と一緒に決める |
| スライドの意図 | `chapters[].slides[].intent` | この 1 枚で聴衆が何を分かるか | 進行役が案として書き、スライドコンテで利用者が見て決める |
| スライドのつながり | `chapters[].slides[].link` | 前のスライドから、なぜこの 1 枚に進むか（任意） | スライドの意図と一緒に書く |

意図の書き方:

- **意図は聴衆の側から書く。** 「ここで聴衆は、UX が画面の中だけの話ではないと分かる」のように、誰が、何を知っていて、ここで何が分かるかを書く。「ここで定義を説明する」のような作り手の都合では書かない
- **利用者が必ず入れたいと言った内容は、意図の文に書く。** 章（またはスライド）の意図の文に、その内容を書き込む。構成メモに、内容を並べる別の欄はない。評価役は、意図に書かれたことがスライドか原稿にあるか、意図にないことを足していないかを見る
- **意図には出どころを求めない。** 意図は事実ではなく狙いであるため、`by: source` にしなくてよい。事実の出どころは、原稿の行の `source` とスライドのテキストの `source` に書く（`storyboard.md` の 3 章と 8 章）。調べて分かった事実そのものは、取材メモ（`brief.md`）に置く
- **比べる章やスライドでは、どちらが主役かも書くとよい。** 「UX を分かってもらうために、狭い範囲のユーザビリティと比べる」のように書くと、スライドの強調や原稿の主語が主役に向く。主役が書かれていないと、比べる相手の説明に寄ってしまうことがある
- スライドの意図は、スライドの切り方と一緒に決まる。進行役が `by: claude`・`state: proposed` で書き、そのままスライドコンテに出してよい。利用者が見て通したら `agreed` にする

## 項目

`basics` の値、`flow`、章とスライドの `intent`・`link` は、どれも同じ形の「項目」で書く。

```json
{ "text": "…", "by": "user", "state": "agreed", "source": ["場所か引用"] }
```

- `text`: 中身を 1 文か 2 文で書く。利用者の答えは、言い換えずに利用者の言葉のまま書く
- `by`: その項目の出どころ
  - `user`: 利用者が言った
  - `claude`: Claude が決めた
  - `source`: 資料や Web から取った。`source` に場所か引用を 1 つ以上書く（書き方は台本の `source` と同じ。`path:line`、`https://… 「引用」` など）
- `state`: 利用者がその項目を見たか
  - `proposed`: Claude が決めたが、利用者はまだ見ていないか、答えていない
  - `agreed`: 利用者が言ったか、見て通した
- `by` が `user` の項目は、必ず `agreed` にする
- `by` と `state` は別のことを表すので、ほかの組み合わせはどれも書ける。Claude が調べて決めた項目（聴衆が知っている前提を資料から拾った、など）で、利用者がまだ見ていないものは、`by: source`・`state: proposed` になる

## 形

| 場所 | 形 | 検査 |
|---|---|---|
| `format` | `"ugoku-zukai-outline/2"` | 違えば誤り |
| `title` | 動画の題 | なければ誤り |
| `basics` | オブジェクト。キーは自由で、値は項目 | オブジェクトでなければ誤り |
| `basics.length.seconds` | 正の数（任意）。長さを秒で書く | 数でなければ誤り |
| `basics.look.theme` | 文字列（任意）。テーマの名前かパス | 文字列でなければ誤り |
| `basics.voice.speaker`・`speed` | 整数・正の数（任意）。台本の `voice` と同じ | 形が違えば誤り |
| `flow` | 章の順番の意図。項目 | 形が違えば誤り |
| `chapters` | 配列。まだ章がなければ空にする | 配列でなければ誤り |
| `chapters[].id` | 英数字・`_`・`-`・`.`・かな漢字。`/` `:` 空白は使えない（台本の id と同じ規則） | ない・重複は誤り |
| `chapters[].title` | 章の題 | なければ誤り |
| `chapters[].intent` | 章の意図。項目 | 形が違えば誤り |
| `chapters[].link` | 前の章からのつながり（任意）。項目 | 形が違えば誤り。最初の章にあれば警告 |
| `chapters[].seconds` | 正の数（任意）。章の長さの目安 | 数でなければ誤り |
| `chapters[].slides` | スライドの配列（任意）。台本で最初に出る順に書く | 配列でなければ誤り |
| `chapters[].slides[].id` | 台本の `slides` のキーと同じ id | ない・重複は誤り |
| `chapters[].slides[].intent` | スライドの意図。項目 | なければ誤り |
| `chapters[].slides[].link` | 前のスライドからのつながり（任意）。項目 | 形が違えば誤り |
| `open` | 文字列の配列（任意）。まだ決めていないこと | 形が違えば誤り |

章に `says`・`shows` を書くと誤りになる（前の形式の欄）。

`basics` の項目は固定の一覧ではなく、会話で出てきたものを書く。よく使うキーは次のとおり。

| キー | 中身 |
|---|---|
| `audience` | 聴衆（動画を見る人） |
| `knows` | 聴衆が知っている前提。意図が聴衆に向いているか、原稿が聴衆に分かる言葉で書かれているかの物差しになる |
| `takeaway` | 持ち帰ってほしいこと |
| `can_do` | 見終わったらできること（概念を伝える動画では、なくてよい） |
| `length` | 長さ |
| `look` | 見た目 |
| `voice` | 声 |
| `tone` | 口調 |

## 台本に進む前に要るもの（`--ready`）

`--ready` を付けると、次のどれかに当たるときも誤りにする。

- `basics` に `audience`・`knows`・`takeaway` のどれかがない。利用者が言わなければ、Claude が案を `proposed` で書く
- `chapters` が空
- 章が 2 つ以上あるのに、章の順番の意図（`flow`）がない
- 意図（`intent`）のない章がある

スライド（`slides`）は `--ready` では見ない。スライドの切り方と 1 枚ごとの意図は、台本と一緒に進行役が案として書き、スライドコンテで利用者が決めるためである。スライドの意図は `proposed` のままスライドコンテに出してよい。

## 台本との突き合わせ

`check_storyboard.cjs --outline` は、構成メモと台本を次のように照らす。

- 場面の `chapter` が構成メモの章を指しているか。章ごとの見積もりの長さが、章の `seconds` から 30% を超えてずれていないか
- 構成メモのスライドと台本のスライドが、同じ id でそろっているか。構成メモにあるスライドが台本にない、台本で使うスライドが構成メモにない（意図が書かれていない）ときは、書きかけの間は警告、`--complete` を付けると誤りになる
- スライドを書いた章が、台本でそのスライドを最初に使う場面の章と同じか（違えば誤り）。章の中のスライドの順が、台本で最初に出る順と同じか（違えば警告）

## 警告

終了コードは変えない。

- すべての章に `seconds` があり `basics.length.seconds` もあるとき、章の合計が長さから 15% を超えてずれている
- 項目の `text` に禁止語（`assets/banned_terms.json`）がある。`by` が `user` の項目は見ない（利用者の言葉はそのまま書くため。字幕に出たときは `check_text.py` が誤りにする）
- 最初の章につながり（`link`）がある

## 守ること

- 章の id は振り直さない。台本の場面は `chapter` で章の id を指し（`storyboard.md` の 3 章）、指摘や直しも章の id で指すため、途中で変えると結び付きが切れる。章を消したら、その番号は欠番にする
- スライドの id は、場面の id（`s1`…）と紛れない名前にする（`ux-def`、`relation`）。構成メモと台本を同じ id で結ぶので、片方だけを変えない。案を選ぶときも、この id で呼ぶ
- スライドは、最初に出る章にだけ書く。後の章でもう一度使っても、構成メモに 2 度は書かない
- 利用者が見て通した項目は、`by` を変えずに `state` だけを `agreed` にする。利用者が文を直したら、`text` を利用者の言葉に書き換えて `by` を `user` にする
- まだ決めていないことは、項目にせず `open` に書く（`open` は文字列の配列。ほかの項目のように `by` を付けない）
- **章の `seconds` は、進行役が章の意図と全体の長さから割り振る。** 意図の重さ（聴衆にとって新しいことが多い章か、前置きの章か）を見て、`basics.length.seconds` を章に分ける。台本を書くと、突き合わせが章ごとの見積もりを出す。目安を超えそうなら、長さを延ばすか、章の意図を絞るかを決める（任されていないときは利用者に聞く）
- **聴衆が知らない語を使う章では、その語の意味が分かることまでを意図に含める。** `basics.knows` にない語を説明なしに出すと、評価役が must にする（O-D3・S-W5）。規格・原典・業界で決まっている用語は、やさしい言葉に置き換えずにそのまま使い、スライドか原稿で説明を足す（置き換えると、元の語と範囲がずれて誤解のもとになる。SP-16）。題材の内部の呼び名で、聴衆が知る必要のないものは、出さない（SP-3）

## まだ確認していない項目の一覧

`--json` の `proposed` に、`state` が `proposed` の項目が書いてある順に入る。進行役が、利用者がまだ見ていない項目を会話で伝えるときに使う（スライドコンテのページには、この一覧は出ない）。

```json
{ "where": "スライド「ux-def」の intent", "label": "スライド ux-def の意図", "text": "UX の定義の文そのものを読み、範囲が使う前・使っている間・使った後に及ぶと分かる" }
```

`where` は項目の場所（`basics.look`、`flow`、`章「c2」の intent`、`スライド「ux-def」の link`）、`label` は人が読む名前（`見た目`、`章の順番の意図`、`章 c2 の意図`、`スライド ux-def のつながり`）である。

## 前の形式（ugoku-zukai-outline/1）

前の形式は、章ごとに「言うこと」（`says`。項目の配列で、各項目に `c3.1` のような id が付く）と「見せるもの」（`shows`。項目に図の種類の目安 `figure` を足せる）を持つ。`flow`、`intent`、`link`、`slides` はない。過去の作業フォルダを直すために、道具は今も読める。

- 検査（`check_outline.py`。`--ready` は、どの章にも `says` があることを見る）、台本との突き合わせ（章と長さだけ）、コマ、声、組み立ては、前と同じに動く
- スライドコンテは、章の題とコマと原稿だけが出る（意図がないため）
- 新しく作る動画には使わない。前の形式を今の形式に上げる道具はないので、過去の作業フォルダは前の形式のまま直す
