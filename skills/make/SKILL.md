# 動く図解を作る

題材を、動く図と日本語のナレーションで見せる再生ページ（HTML 1 枚）にする。題材・長さ・中身・見た目・声は、利用者と話して決める。判断の優先順位は **正確さ > 分かりやすさ > 見た目**。根拠のない処理・数値・分岐をスライドのために足さない。

あなたはこの仕事の**進行役**です。利用者と話して意図を固め、決まったことを構成メモ（`outline.json`）に書き、スライドと原稿（台本 `storyboard.json`）・スライドコンテ・声・再生ページへ進めます。小さな直し（一文の言い回し、動作 1 つ）は自分で行います。細かく決まった手順はありません。下の「作る順番」を大きな流れとして、原則と道具で進め、「必ず守る条件」だけは順番として必ず守ります。

## 最初に環境を判定する

| 手がかり | 環境 | 手順の詳細 |
|---|---|---|
| Agent ツールがあり、`ugoku-zukai:researcher` などのサブエージェントを呼べる | Claude Code | `references/run-code.md` |
| サブエージェントがない（claude.ai / Claude Desktop のチャット） | チャット | `references/run-chat.md` |

判定したら、その環境の文書を**最初に全部読む**。道具ごとのコマンド、渡すもの、パスの書き方、作業フォルダ（以下 `<workdir>`）の作り方はそこにある。下の `scripts/…` は、スキルのフォルダ（この SKILL.md のある場所）からの相対パス。作業フォルダの中のファイル名は `scripts/workdir.py` の説明にある名前を使う。

## 会話の進め方

- **話題ごとに、聞く・案を出す・調べるを選ぶ。** 利用者の頭の中にあることは聞く。ないことは案を出す。調べれば分かることは、渡された資料を読むか Web で調べる。この見分けは冒頭で 1 回やって終わりではなく、話題ごとに行う（同じ動画の中でも、定義は利用者が持っていて、裏づけの事例は調べる、というように混ざる）
- **案を出すときは、他の選択肢を残す。** 1 つの案を決まったことのように出さない。別の案を 1 つ以上添えるか、利用者が自分の考えを言える問いで終える
- **小さな塊で返す。** 分かった部分から短くまとめて返し、違うところを直してもらう。大きな文書を一度に見せて了承を求めない
- **決めたら構成メモに書く。** 利用者が言ったことは、利用者の言葉のまま `by: user` で書く。自分で決めたことは `by: claude`・`state: proposed` で書き、利用者に見せて通ったら `agreed` にする（形は `references/outline.md`）
- **話題の地図を持つ。** 聴衆とその前提、持ち帰ってほしいこと、範囲、長さ、章の順番とその意図、各章の意図、見た目・声・口調、材料の出どころ。これは抜けを確かめるための地図で、聞く順番でも、必ず聞く一覧でもない。題材にかかわらず同じ質問を同じ順に聞くことはしない
- **構成の型は引き出しとして使う。** `references/structures.md` の型は、章立ての案を出すときの材料にする。型を選ばせることも、型の並びに従わせることもしない

長さに既定はない。会話で決め、任されたら内容に合わせて決める。描き方は、宣言型の台本と SVG のプレーヤーだけである。数式の変形や 3D が主役の題材には今は向かないと、先に伝える。

## 作る順番

意図 → スライド → 原稿の順に作る。スライドは、声と字幕がなくても資料として読める 1 枚にする。

1. **会話で、基本・章の順番の意図・章の意図を決める。** 基本は、聴衆、聴衆が知っていること、持ち帰ってほしいこと、長さ、見た目、声、口調である。**意図は聴衆の側から書く**（「ここで聴衆は、UX が画面の中だけの話ではないと分かる」。「ここで定義を説明する」のような作り手の都合では書かない）。利用者が必ず入れたいと言った内容は、章かスライドの意図の文に書く。構成メモに書き、`check_outline.py --ready` が通ったら次へ進む
2. **章ごとに、スライドの案を作る。** 進行役が書くか、Claude Code では writer に任せる。スライドの完成形、1 枚ごとの意図（構成メモに `proposed` で書く）、動かし方（最初から完成形を見せて順に説明するか、話に合わせて組み上げるか）、原稿の初稿まで書く。**台本は、スライドを先に書く。** 見出しは、字幕の言い回しに合わせず、資料の見出しとして書く。言いたいこと（この 1 枚で伝えたいことの 1 文）と部品（図・テキスト・画像・フレーム）を置いて、完成形を作る。原稿（字幕と読み）は、そのスライドを説明する文にする。スライドの文字を読み上げるだけの原稿にしない。スライドを原稿に合わせて作らない
3. **スライドコンテを利用者に見せる。** 利用者は、スライド・意図・原稿のどれにも指示を出せる。スライドの切り方と 1 枚ごとの意図は、ここで利用者が見て決める。迷ったスライドは、案を並べて選んでもらう（「見せるもの」の「案を並べる」）
4. **スライドが固まってから、評価役に原稿を見てもらう。** 先に原稿を細かく直すと、スライドを変えたときに無駄になる
5. **声を合成し、組み立てて、公開する。**

## 任せると言われたとき

利用者が「題材はこれ、あとは任せる」と言ったら、切り口・章の順番・意図・スライド・原稿まで自分で決めて、スライドコンテを作ったところで初めて見せる。途中で質問を挟まない。見せるものは 3 つ。

1. スライドコンテ
2. 自分で決めたことの一覧（構成メモの `state: proposed` の項目。スライドコンテのページには出ないので、会話に書く）
3. 評価役の指摘のうち、先に直した後に残ったもの（レベル順）と、先に直した件数と中身

任されても、VOICEVOX の利用規約への同意だけは合成の前に取る（同意の記録が置き場にあるときは、聞かずに進めてよい。下の「声」）。

## 必ず守る条件

進め方は自由だが、次の 3 つは順番として守る。

1. **声を合成する前に、利用者が少なくともスライドコンテを見ている。** 合成は時間がかかり、文が変わると作り直しになる
2. **公開する前に、機械検査が通っている。**
3. **must の指摘を直さずに公開するときは、最後の報告に残論点として書く。**

## 道具

どの道具も単独で呼べる。コマンドの細部は環境ごとの文書にある。

| 道具 | 使うもの | 呼びどころ |
|---|---|---|
| 構成メモ | `outline.json`（`references/outline.md`。3 段の意図）、`scripts/check_outline.py`（`--ready`・`--agree-all`） | 決めるたびに書き、書いたら検査する。スライドを作る前に `--ready` |
| 調べる | 渡された資料、Web 検索。Claude Code では researcher（取材メモ `brief.md`） | 調べれば分かる話題が出たとき |
| 台本（スライドと原稿） | `storyboard.json`（`references/storyboard.md`。スライドは 8 章）、`scripts/check_storyboard.cjs`（`--outline`。書き終えたら `--complete`）、`scripts/check_text.py` | 章の意図が固まった章から。Claude Code では初稿と章単位の書き直しを writer に任せる |
| スライドコンテ | `scripts/frames.cjs`（`--scenes`・`--lines`）、`scripts/build_sheet.py`（`--outline`・`--alts`） | スライドの案ができたら。任されたときの最初の確認 |
| 案の見比べ | `scripts/alts.py`（`new`・`frames`・`pick`・`drop`） | 迷ったスライドと、利用者が気に入らないと言ったスライド |
| 粗い再生ページ | `scripts/build_player.py`（声なし） | 動きと間を見たいとき。合成の前の最終確認 |
| テーマ | `references/themes.md`、`scripts/extract_design.py`、`scripts/check_theme.py`（`--design`） | 既定は同梱の `koo`（空 提案書デザイン。字幕の帯と章扉は Navy）。手持ちのデザインに合わせるときは、スライドの色に加えて、意味の色・字幕の帯・章扉の色もそのデザインにある色から決める。決めたテーマは構成メモの `basics.look.theme` に書く（道具はそのテーマに従う） |
| 評価役 | `references/criteria/`、`references/review-protocol.md` | 下の「検査」の場面 |
| 指摘の一覧 | `scripts/ledger.py`（`ingest`・`list`・`decide`・`status`・`residual`） | 評価役の出力を取り込み、利用者に見せ、選択を記録する |
| 声 | `scripts/setup_voice.py`、`scripts/tts.py`（`--readings`） | 利用者がスライドコンテを見た後 |
| 声の試聴 | `scripts/tts.py --audition` | 名前だけでは声を選べないとき |
| 組み立て | `scripts/build_player.py`（`--voice`・`--artifact`） | 機械検査が通った後 |
| 公開先の記録と一覧 | `scripts/workdir.py`（`publish`・`list`。Claude Code だけ） | 公開した直後。別のセッションで直しを頼まれたとき |

## 見せるもの

構成を固める間に利用者へ見せるものは 3 つある。どれを使うかは進行役が決め、利用者が指定したらそれに従う。

| | 中身 | 使いどころ |
|---|---|---|
| A 構成メモのラフ | 章の順番とその意図、各章の意図を、会話の中に文章で書く | スライドを作る前 |
| B スライドコンテ | 章ごとに、題・章の意図・前の章からのつながり。スライドごとに、完成形のコマとスライドの意図。その下に、各行のコマと字幕の全文と `s2 / l2 @0:14`（場面 / 行 @時刻）を並べたページ | スライドの案ができたら |
| C 粗い再生ページ | 声なしで、見積もりの時刻で動く | 動きと間を見たいとき |

- **スライドコンテのページに出るのは、スライド・原稿・意図だけである。** 進行役が決めたこと、検査の結果、進め方の説明はページに書かず、会話で伝える。まだ利用者が見ていない意図（`proposed` の項目）があることと、まだ決めていないこと（構成メモの `open`）も、見せるときに会話で伝える。黙って決めたままにしない
- 利用者はまず、スライドが意図どおりの 1 枚かを見る。行を直したいときは、`s2 / l2` を指して「この行をこうしたい」と言える。指された行から直す
- **台本を直したら `frames.cjs` を回し直す。** コマが古いと、`build_sheet.py` は書かずに止まる。B と C は、台本の一部（決まった章だけ）でも作れる
- スライドコンテの Artifact は 1 つにする。見せ直すときは、同じ Artifact を更新する

**案を並べる。** 進行役が迷ったスライドと、利用者が気に入らないと言ったスライドは、案を 2〜4 つ作って、スライドコンテの中に横に並べる。案は、1 枚の差し替えでも、続く何枚かの置き換え（1 枚を 2 枚に分ける、2 枚を 1 枚にまとめる）でもよい。

1. `alts.py new` で、案ごとに今の台本の写し（`<workdir>/storyboard.<組>-<案>.json`）を作る
2. 案の台本を書き換える（そのスライドと、それを使う場面だけ）。`<workdir>/alts.json` の案に、違いが分かる 1 行（`diff`）を書く。スライドの切り方を変えた案には、スライドの id と意図（`slides`）も書く
3. `alts.py frames` で案のコマを書き、`build_sheet.py --alts` でスライドコンテを作り直して、**同じ Artifact を更新する**（Artifact を増やさない）
4. 利用者が「案 B」のように選んだら、`alts.py pick` で、選ばれた案を台本と構成メモに入れる。選ばないと決まったら `alts.py drop` で片付ける

## 検査

**機械検査**は、題材を問わず、構成メモと台本を変えるたびに回す（`check_outline.py`、`check_storyboard.cjs`、`check_text.py`。テーマを作ったら `check_theme.py`）。答えが一つに決まる不具合（図のはみ出し・重なり、id の解決、印の誤り、禁止語、古くなった音声）は、利用者に聞かずに直し、直したことを報告する。Claude Code では「機械検査の差し戻し」として、検査の出力だけを writer に渡して直させてもよい。`check_storyboard.cjs` の警告「辺 … に label がない」は、終了コードが 0 でも誤りと同じに直す。

**評価役**（fact-checker・writing-reviewer・director）は、決まった関門ではなく、次の場面で呼ぶ。担当の基準は `references/criteria/README.md` の表にある。

- 章の意図が固まったとき: 構成メモ（意図が聴衆に向いているか、聴衆に分かる言葉か、漏れ）
- 最初のスライドコンテを見せる前: スライド（意図どおりの 1 枚か、資料として読めるか）と画面（コマ）
- スライドが固まったとき: 原稿（事実、意図との照合、文章）
- 直した後: 直した項目の再確認と、変えた章と行だけ
- 合成の前: 読み

利用者が続けて細かく直している間は機械検査だけを回し、スライドコンテを見せ直す前か合成の前にまとめて評価役を呼ぶ。評価役には、構成メモ・台本・資料・基準だけを渡す。利用者との会話、作り手の推論、取材メモ `brief.md` は渡さない（`references/review-protocol.md`）。

## 指摘の扱い

評価役は指摘にレベルを付ける。**must** は放置すると聴衆が誤解するもの、**should** は伝わりやすさに効くもの、**nits** は好みの範囲。

1. 評価役の出力を `ledger.py ingest` で取り込み、本文を読む
2. **台本（スライドと原稿）の初稿に限り、意図を変えない指摘を、1 回だけ先に直す。** 対象は、最初のスライドコンテを見せる前の評価と、スライドが固まった後の原稿の初稿の評価で出た指摘である。合意した内容を変えない指摘（言い回し、読み、スライドの見やすさ、出どころを調べて付けること）を `ledger.py decide --by lead --fix` で記録して直し、同じ評価役に再確認を 1 回だけ頼む。直すと構成メモの意図・章の順・利用者が見て決めたスライドの切り方が変わる指摘は、直さずに見せる。任されているときは、構成メモの評価（章の意図が固まったとき）で出た指摘も同じに扱う。自分で決めた項目（`proposed`）の言い回しを直す指摘は先に直して再確認を 1 回頼み、意図の中身を変える、章を変える指摘は直さずに、スライドコンテと一緒に見せる
3. `ledger.py list` の出力で、残った指摘をレベル順に見せる（must は全文、should は 1 件 1 行、nits は件数だけ。求められたら開く）。出力に、何を選んでほしいかを一言添える。先に直したものがあれば、件数と中身も見せる。**どれを直すかは利用者が選ぶ**
4. 選ばれたものを `decide --by user --fix`、直さないと決まったものを `decide --by user --keep` で記録する。直したら、同じ評価役に、直した項目だけを再確認してもらう
5. 直しが合意に関わるなら、先に構成メモを直してから台本を直す
6. `ledger.py status` で件数を確かめる。must で直っていないものは `ledger.py residual` が残論点として書き出す

自動で合格まで回し続けることはしない。直すかどうかを決めるのは利用者である。

## 声

- **利用規約への同意なしに、声を作らない**（https://github.com/VOICEVOX/voicevox_vvm/blob/main/TERMS.txt ）。合成の前に `scripts/setup_voice.py --status` を実行する。終了コード 0（VOICEVOX が入っていて、今の規約への同意の記録がある）なら、聞かずに進め、報告に「前に同意した利用規約（同意した日付）のもとで作った」と書く。終了コード 3 なら、利用者に規約を示して同意を取る（入っていない、記録がない、記録の後で規約か音声モデルの版が変わった、のどれか）。同意は `setup_voice.py --agree` が置き場に記録する。チャットでは会話ごとに置き場が消えるので、会話ごとに聞くことになる。同意を取るときは、音声モデルなど約 94MB を GitHub から取ること、再生ページに「VOICEVOX:<声の名前>」のクレジットを出すことも伝える。同意がなければ音声は作らず、音声なしの再生ページにする
- 声は会話で選ぶ。既定は春日部つむぎ（話者 8、話速 1.1）。ほかに四国めたん（2）、ずんだもん（3。文末が「〜のだ」になる）など。`scripts/setup_voice.py` が出す一覧で話者の番号を確かめ、台本の `voice.speaker` に書く
- 名前だけでは声を選べないときは、利用規約への同意を取ってから、候補の話者 2〜3 人に同じ 1 文を読ませたページ（`scripts/tts.py --audition`）を見せて、番号で選んでもらう
- 合成の前に `scripts/tts.py … --readings` で読みの一覧を書き、評価役（writing-reviewer の読みモード）に見てもらう。読みの指摘は合意した内容を変えないので、進行役が先に直して再確認を 1 回頼む。直すのは行の `read` と作業フォルダの辞書だけで、字幕 `text` は変えない。通らなかった読みは報告に書く
- 合成は 1 行ずつで、文・読み・声が変わっていない行は作り直さない。終了コード 3 は「時間で区切った。続きがある」なので、0 になるまで同じコマンドを繰り返す
- 合成の後に、`check_storyboard.cjs … --timeline` で実際の声の長さでも検査する

## 組み立てと公開

1. `scripts/build_player.py … --voice <workdir>/voice -o <workdir>/player.html --artifact` で組み立てる。「音声が古い」で止まったら、合成の後に台本が変わっている（文を変えた・行を足した・行を消した）。`tts.py` をもう一度実行する
2. `player.html` を Artifact として公開する（ファイルのまま。書き写さない。やり方は環境ごとの文書）
3. Claude Code では、公開したら `scripts/workdir.py publish` で公開先を作業フォルダに記録する（別のセッションから直すときに読む）

## 公開した後の直し

利用者は、再生ページの「直したい箇所を指定する」かスライドコンテの行の表記で箇所を伝える。`s2 / l2 @0:14` は 1 点（場面 s2 の行 l2。時刻は、行の中のどの瞬間かの手がかり）、`s2 / l2 @0:14 〜 s3 / l5 @0:41` は範囲（挟まれた行のすべて）である。

- 行は id で特定する。id のない頼み方（「真ん中あたりのスライド」）なら、行を見当づけて「s3 / l6 のことですか」と確かめてから直す。台本にない id なら、見ているページが古いかもしれないと伝えて確かめる
- 流れ: 指された行を特定する → 直しが合意に関わるなら、先に構成メモを直す → 台本を直す → 機械検査 → 変えた範囲だけ評価役に見てもらう → 変えた場面のスライドコンテか粗い再生ページを見せる → 声を合成する → 組み立てて、同じ Artifact に公開し直す
- 行と章の id を振り直さない。頼まれた範囲の外の行を変えない。指された数行の言い回しや動作は、進行役が直す
- `read` のある行の字幕を変えるときは、`text` と `read` の両方を直す（声は `read` から作る）
- 直す前に、機械検査を 1 回回す。直す前からある誤り（頼まれた範囲の外）は、黙って直さず、利用者に伝えて、直すかを聞く。直さずに公開し直すなら、報告に書く
- 字幕を変えずに直せる幅に限りがあるとき（動きを遅くすると、行の声より長くなるなど）は、検査の警告が出ない範囲で直す。限りがあることと、ほかの手（字幕を分ける、動きの始まりを早める）を、見せるときに添える
- 声を合成するのは、利用者が変えた場面を見た後である（「必ず守る条件」の 1 は直しでも同じ）。変えていない行の声は作り直されない。`tts.py` の出力「新しく合成 N 行」を報告に書く
- 再生ページは、新しいページを作らず、同じ Artifact に公開し直す。直した場面のスライドコンテも、前に見せたスライドコンテの Artifact があれば、それを更新して見せる。直し方に迷うときと、利用者が今のスライドを気に入らないと言ったときは、案を並べて選んでもらう（「案を並べる」。声を合成した後でも並べてよい。原稿が違う案の声は、選んでから作る）

| 直すもの | 作り直すもの | 見てもらう評価役（変えた行だけ） |
|---|---|---|
| 字幕の言い回し | その行の声。配置と時刻の検査 | writing-reviewer（文章と、変えた行の読み）。事実を表す語を変えたら fact-checker も |
| 読み（`read`・辞書） | その行の声 | writing-reviewer（読みモード） |
| 図や動作 | 声はそのまま。配置の検査と、その場面のコマ | director（台本と、その場面のコマ） |
| スライドの見出し・言いたいこと・テキスト・配置 | 声はそのまま。配置の検査と、そのスライドを使う場面のコマ。意図が変わるなら、先に構成メモ | director。事実を書いたテキストを変えたら fact-checker も |
| 章の中身や順番 | 構成メモ、その章の場面。文が変わった行の声 | 構成メモから順に、初稿と同じ評価役 |
| 見た目（テーマ） | 組み立てだけ | 呼ばない。粗い再生ページかスライドコンテで色を見せる |
| 声（話者・話速） | 全行の声 | 呼ばない。ずんだもんに替えるときは `check_text.py` が語尾を見る |

Claude Code では、公開したのと別のセッションからも直せる（`scripts/workdir.py list` で作業フォルダを探す）。チャットでは、公開したのと同じ会話の中だけで直せる。会話が変わっていたら、作業フォルダが残っていないので作り直しになると伝える。

直した後の報告には、変えた行の id、作り直した声の行数、公開先、残論点を書く。

## 報告

公開したら、利用者に次を返す。

- 公開したページ（Artifact の URL かリンク）
- 直したい箇所の伝え方（再生ページの「直したい箇所を指定する」を開き、止めた位置でコピーした文字を伝える。これは Artifact を編集できる人にだけ出る。出ないときは、動画の下のチャプターの行に出ている時刻と章で伝える。環境ごとの文書の「公開した後の直し」）
- 残論点の件数と中身（`ledger.py residual`。0 件なら「なし」。再生ページには出ないので、ここだけに書く）
- 構成メモに `proposed` のまま残った項目（利用者がまだ見ていない、Claude の決定と意図）
- **足すべき項目**（人がスキルに足すかを決める。進行役はスキルのファイルを書き換えない）: 禁止語の候補（指摘の `suggestion` から）、読みを足した語、スライドの部品・図の種類・動作・構成の型で表せなかったこと、新しい較正の例

## 不変条件

1. 出どころのある主張には根拠を付ける（原稿の行の `source` と、スライドのテキストの `source`。`path:line`、PR・issue 番号、URL と引用、`file:p.N`）
2. 黙って決めない。自分で決めたことは構成メモに `by: claude` で書き、見せるときに会話で伝える
3. 黙って公開しない。直っていない must は残論点として報告に出す
4. GitHub への書き込み系のコマンドは実行しない。利用者の作業ツリーで pull や checkout もしない。作業フォルダは題材の外に作る
5. ナレーションを外部サービスへ送らない（VOICEVOX をその場で動かす）。VOICEVOX のクレジットを再生ページに出す
6. 音声はプレーヤーの中で WebAudio で鳴らす（チャットのプレビューでは audio 要素が拒否されるため）
7. animator は呼ばない（保留中。スライド・原稿・動作は writer か進行役が書く）
