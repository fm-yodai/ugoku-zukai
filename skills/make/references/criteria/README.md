# 成功基準（作り手と評価役が共有する物差し）

合格の条件を、対象ごとのファイルに分けて書く。**作り手（進行役・writer）は書く前と渡す前に、評価役（fact-checker・writing-reviewer・director）は判定するときに、同じこのファイル群を読む**。基準の言い回しを変えると両方の振る舞いが変わるので、変えるときは較正の例も見直す。

**物差しは意図である。** 構成メモ（`outline.json`。形式は `../outline.md`）には、章の順番の意図（`flow`）、章の意図（`intent`）と前の章からのつながり（`link`）、スライドの意図とつながり（章の `slides`）が書いてある。評価役は「意図どおりのスライド・原稿になっているか」を見る。一番上の約束は、**聴衆のことを考えない、独りよがりな動画にしない**ことである。そのため、意図そのものが聴衆の側から書いてあるかも、基本（`basics`）の聴衆（`audience`）・聴衆が知っていること（`knows`）・持ち帰ってほしいこと（`takeaway`）に照らして見る。

| ファイル | 対象 |
|---|---|
| `outline.md`（O-） | 構成メモ `outline.json`（基本と、3 段の意図） |
| `agreement.md`（A-） | 台本 `storyboard.json` のスライドと原稿が、構成メモの意図どおりか |
| `structure.md`（G-） | スライド（見出し・言いたいこと・部品・区画）と、部品として置いた図 |
| `script.md`（S-） | 原稿（各行の字幕 `text`・読み `read`・根拠 `source`・動作 `do`）、スライドのテキストに書かれた事実、読みの一覧 `voice/readings.md`（S-W8・S-W9） |
| `screen.md`（V-） | `frames/` の行ごとのコマ（`sheet-NN.png`・`svg/<行 id>.svg`・`frames.json`）と、`check_storyboard.cjs` の配置の結果 |

この文書群では、台本のうち、スライドの宣言（`slides`・`figures`）を「スライド」、場面の行（字幕・読み・根拠・動作）を「原稿」と呼ぶ。

## 評価役を呼ぶ場面

評価役は、決まった順番の関門ではなく、次の場面で進行役が呼ぶ。`target` は評価役に渡す名前で、評価役の出力（`../writing/review-format.md`）にも書く。

| 呼ぶ場面 | `target` | 評価役と担当の基準 |
|---|---|---|
| 章の意図が固まったとき | `outline` | director: O-D1〜O-D9。fact-checker: O-F1・O-F2（資料のある題材か、`by` が `source` の基本の項目があるとき） |
| 最初のスライドコンテを見せる前（スライド） | `script` | director: A-1〜A-5、G-D1〜G-D7、G-D9・G-D10、G-D11〜G-D16、S-D1・S-D2・S-D4。見るのはスライドの宣言と完成形のコマ。原稿は、意図に書かれたことの在りかを探すときだけ読む |
| 最初のスライドコンテを見せる前（コマ） | `screen` | director: V-1〜V-6、G-D5、G-D8 |
| スライドが固まった後（原稿） | `script` | fact-checker: S-F1・S-F2・S-F4・S-F5。writing-reviewer: S-W1〜S-W7、S-W10・S-W11、S-W12・S-W13。スライドを変えていたら、director に変えたスライドだけを見てもらう |
| 合成の前 | `voice` | writing-reviewer（読みモード）: S-W8・S-W9 |
| 直した後 | 元と同じ | 直した項目の再確認（`rechecks`）と、変えた章・スライド・行に限った判定 |

原稿を細かく見るのは、スライドが固まった後である。先に原稿を細かく直すと、スライドを変えたときに無駄になる。利用者が続けて細かく直している間は機械検査だけを回し、スライドコンテを見せ直す前か合成の前にまとめて評価役を呼ぶ。

## 項目の読み方

各項目は「ID・合格の条件・検査（機械 / どの評価役）・重さ」を持つ。

- **合格の条件は、何を見て、どうなら FAIL かが分かる文**にしてある。点数は付けない。意図に照らす基準は、数では決まらない。評価役によって判定がぶれることは受け入れる（利用者が決めた）。その代わり、根拠を必ず書く
- **意図に照らした判定には、意図のどの文に照らしたかを書く。** `evidence` に、照らした意図の場所（`c2` の `intent`、スライド `ux-def` の `link`、`flow`、`basics.knows` など）と、その文の引用を入れる。意図の引用のない判定は、何に照らしたのかが分からないので、根拠のない判定として扱う
- **検査が「機械」の項目は評価役が判定しない**。進行役が `check_outline.py`・`check_storyboard.cjs`・`check_text.py` を回し、誤りは指摘の一覧に載せずに直す。評価役は機械の結果を読んでよいが、重ねて指摘しない
- 情報が足りなくて判定できなければ **UNKNOWN** を返す（推測で PASS / FAIL にしない）。UNKNOWN は must の指摘として指摘の一覧に載る
- **根拠のない判定は無効**。FAIL には場所と引用（`path:line`・URL と引用・字幕やスライドの文言・「`sheet-02.png` の行 `l7`」のようなシートのファイル名と行 id）、PASS には確認した範囲を書く
- 「対象外」と書いた条件に当たるとき（資料のない題材の O-F2 など）は PASS とし、`evidence` に対象外の理由を書く
- 構成メモにスライドが書かれていない台本（前の形式の作業フォルダ。場面が `figure` を指す）では、スライドの意図に照らす基準（A-3・A-5、G-D11〜G-D15、V-6）は対象外にする

## スライドと原稿の役割

基準は、次の役割分担を前提にしている。

- **スライドは、声と字幕がなくても資料として読める 1 枚である。** 見出し（`title`）、言いたいこと（`statement`）、部品（図・テキスト・画像・フレーム）でできている
- **原稿は、スライドを説明する文である。** スライドの文字を読み上げるものではない。スライドが原稿をなぞるのでもない
- スライドの見出しと字幕の言い回しを合わせることは求めない。見出しは資料の見出しとして、字幕は話し言葉として書く
- スライドのテキストは書き言葉なので、かける文章の規則は書き言葉の規則（TW-）だけである。話し言葉の規則（SP-）は、字幕と読みにかける

## 重さとレベル

評価役は指摘にレベル（`must`・`should`・`nits`）を付ける。意味は `../writing/review-format.md` の「レベル」。

- 重さが `must` だけの基準の指摘は must。評価役がほかのレベルを付けても、`ledger.py` が must に直して取り込む（過去に、事実の言い過ぎが should で付き、直されないまま残った）
- 重さが `should` の基準と、must と should を分けている基準では、定義に従って付ける。直さなくても伝わり方が変わらないものは nits にする

既存の規則は転記せず ID で参照する: 文章 `TW-n`（`../writing/rules.md`）、聞いて分かる文 `SP-n`（`../writing/spoken.md`）、演出 `VG-n`（`../visual-grammar.md`）。

## 衝突したとき

評価役どうしの指摘が食い違ったら、**事実 > 合意 > 構造 > 文章 > 演出** の順で上を採る（`../review-protocol.md`）。「合意」は、利用者と合意した意図（A- と O-）を指す。

## 較正の例

各ファイルの末尾に、人の指摘や過去の画面レビューで実際に出た欠点を「較正の例」として置く。評価役はこの例と同程度の欠点を見逃していないかで、自分の甘さを点検する。新しい欠点を人が見つけたら、最後の報告の「足すべき項目」に挙げ、人がここに足す（題材固有の名前は書かず、何が悪く、どの基準で止めるかを書く）。前の進め方のときの例は、今の言葉（意図・スライド・原稿）に直して残してある。意図に照らす基準には、実際の通しで出た例がまだ少ないので、「判定の目安として置いた例」と断った例を置いてある。通しで実際の欠点が出たら、人が置き換える。
