# 聞いて分かる文の規則（SP-）

字幕とナレーションは、画面を見ながら一度だけ聞く文である。読み返せないので、聞いた順に意味が取れることを見る。正確さは `rules.md`（TW-）が見る。指摘は `SP-<番号>` で規則を指す。

| # | 規則 | 悪い例 | 直した例 |
|---|------|--------|---------|
| SP-1 | **冒頭の 1 行目で、何の説明かを素直に言う。** 問いで始めるのは、視聴者の言葉で立てられ、答えが動画の中にある問いのときだけ | 「題材を渡すと、何が起きて再生ページになるのでしょうか」 | 「動画作成プラグイン ugoku-zukai について説明します」 |
| SP-2 | **視聴者の前提にない語は使わない。** 使うなら意味を先に、別の文で言う。名詞の前に説明を重ねない | 「進行役がチャットでページを公開する仕組み Artifact に載せ、共有します」 | 「Artifact は、チャットの中でページを公開する仕組みです。進行役はここに再生ページを載せます」 |
| SP-3 | **スキルや題材の内部の呼び名は、視聴者が知る必要があるときだけ、意味を言ってから使う。** 知らなくても分かるなら出さない | 「ledger.py の status の結果で、次の周に進むか決めます」 | 「指摘の記録を見て、次の周に進むか決めます」 |
| SP-4 | **1 文に 1 つのこと。** 50 字以内を目安にし、並べるのは 3 つまで。4 つ以上は文を分けるか、まとめる言葉で束ねる | 「確認する項目は、出典、数値、固有名詞、用語、経路、順序、単位、抜けの 8 つで、それぞれ別の担当が見ます」 | 「確認する項目は 8 つあります。まず、出典と数値と固有名詞を見ます。次に、用語と経路と順序を見ます。最後に、単位と抜けを見ます」 |
| SP-5 | **印 `{a}` のために読点を増やさない。** 節の切れ目の読点はそのまま残す | 「{a}作り手と、{b}評価役は、別の担当です」 | 「{a}作り手と{b}評価役は、別の担当です」 |
| SP-6 | **「の」を 1 文に 3 つ以上続けない。** 続けて 3 つ出たら、語を言い換えるか文を分ける | 「台本の字幕の読みの確認を行います」 | 「台本の字幕について、読みを確認します」 |
| SP-7 | **比喩・演出・造語をしない。** 同僚に口頭で説明するときの言葉を物差しにする | 「ここが全体の心臓部で、台本が命を吹き込まれます」 | 「ここが中心の処理で、台本から画面と声を作ります」 |
| SP-8 | **名詞と動詞の組み合わせを確かめる。** 声に出して、その動詞を普通その名詞に使うかを見る | 「契約を走らせて、台本を渡します」 | 「契約を書き終えたら、台本の作成に進みます」 |
| SP-9 | **直しすぎない。幼くしない。** 定着した用語（シーケンス図・API・キャッシュなど）を和訳しない。やさしくするために内容を削らない | 「API」を「ソフト同士の話し合いの窓口」と言い換える | 「API」のまま使う。視聴者が知らなさそうなら、初出で 1 文だけ意味を言う |

writer は書く前に読み、書いた後に SP-1〜SP-9 を 1 つずつ見直す。writing-reviewer は `interview.md` の視聴者として初めて聞いたつもりで S-W5〜S-W7 を判定する。
