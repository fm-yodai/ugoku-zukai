# 台本の形式（ugoku-zukai/6）

台本 `storyboard.json` は「どの図を出し、ナレーションのどの語でどう動かすか」を書く。座標や秒は書かない。配置はプレーヤーが ELK などで決め、時刻は字幕の文中の印と音声の時刻表で決まる。評価役は台本だけを読んで「何を見せるか」を照合できる。

場面は**スライド**を指す（8 章）。スライドは、見出し・言いたいこと・区画に並べた部品（図・テキスト・画像・フレーム）でできた 1 枚で、声と字幕がなくても資料として読めるように作る。前の形式（`"format": "ugoku-zukai/2"`。場面が `figure` で図を 1 つか 2 つ指す）と `ugoku-zukai/3` の台本も、そのまま読める。`/4` でも、図だけの場面は `figure` で書ける。`/4` で足したのは、スライドの切り替えで図をつなぐ Morph（部品の `"morph"`、8 章）、本文に寄るカメラ（動作の `"zoom"`・`"pan"`、5 章）、線を伸ばして出す `show` の `"draw"`（5 章）で、これらを `/3` 以前の台本に書くと、検査が「format を "ugoku-zukai/4" と書く」と止める。これらを扱うための捉え方と、それぞれが聴衆に起こすことは `visual-grammar.md` の「キャンバスとカメラ」（VG-10〜VG-12）。`/5` で足したのは、名前付きの値（最上位の `"values"`、1 章）と、値を動かす動作 `"set"`（5 章）、値に連動して描く `custom` の部品（`"type": "custom"`、8 章）で、これらを `/4` 以前の台本に書くと、検査が「format を "ugoku-zukai/5" と書く」と止める。`/4` までの台本は、そのまま読める。値に連動して動く図と数式の変形が聴衆に起こすことは `visual-grammar.md` の VG-13・VG-14、座標・グラフ・数式を描く道具とリファレンスは `geometry.md`。`/6` で足したのは、3D の空間を描く `space` の部品（`"type": "space"`。2D の図を空間に置く板 `plate` を含む。8 章）と、`graph` の箱の中身 `inside`（2 章の `graph`）で、これらを `/5` 以前の台本に書くと、検査が「format を "ugoku-zukai/6" と書く」と止める。`/5` までの台本は、そのまま読める。立体を回して見る・層を起こす・箱の中に入る見せ方が聴衆に起こすことは `visual-grammar.md` の「奥行き」（VG-15〜VG-17）。

見本は `examples/`（スライドの形 `slide-forms.json`、Morph・カメラ・線の描画 `camera-morph.json`、値と数式・グラフ `math-geometry.json`、立体・板・箱の中に入るズーム `depth.json`、業務の流れ・状態遷移・シーケンス図・箇条/比較/表・2 つの図と下の層、提案資料の図 `proposal-*.json`）。書いたら必ず検査する:

```bash
node scripts/check_storyboard.cjs storyboard.json --theme koo     # 形・id・経路・配置
node scripts/check_storyboard.cjs storyboard.json --theme koo --outline outline.json   # 構成メモの章とも突き合わせる（書き終えたら --complete も付ける）
python3 scripts/build_player.py storyboard.json -o preview.html     # 音声なしの下見
```

## 1. 全体の形

```json
{
  "format": "ugoku-zukai/6",
  "title": "経費精算の承認ルート",
  "voice": { "speaker": 8, "speed": 1.1 },
  "values": { "rate": 0.02 },
  "figures": { "flow": { "type": "graph", ... } },
  "slides": { "p-flow": { "title": "承認の流れ", "statement": "…", "parts": [ { "figure": "flow" } ] } },
  "scenes": [ { "id": "s1", "slide": "p-flow", "lines": [ ... ] } ],
  "custom": { "bars": "({ g, v, geo, w, h }) => { ... }" }
}
```

- `voice.speaker` は VOICEVOX の話者 id（既定 8 = 春日部つむぎ。一覧は `setup_voice.py` が出す）、`speed` は話速（既定 1.1）
- クレジットは声から決まる（例「VOICEVOX:春日部つむぎ」）。画面の右下と終わりの札に出る。`credit` で書き換えられる
- `values`（`/5`）は名前付きの値 `{ 名前: 数 }`。動作の `set`（5 章）で動かし、`custom` の部品（8 章）の関数が `v.<名前>` で読む。値は場面をまたいで引き継ぐ（前の場面で動かした後の値から始まる）
- `custom` は、関数を名前を付けて文字列で書く所。`custom` の部品（8 章）と、下の層の `custom` の動作（6 章）が、ここの関数を名前で指す
- id には英数字・`_`・`-`・`.`・かな漢字が使える。`/` `:` 空白は使えない（`図/id` の区切りに使うため）

## 2. 図（figures）の種類

図は `figures` に名前を付けて宣言し、場面から参照する。同じ図を続く場面で使うと、出した部品はそのまま残る。

| type | 用途 | 部品の id（動作の対象） |
|---|---|---|
| `title` | 題。「〜について説明します」の形でも、問いでもよい。場面の頭で自動で出る | `text` `sub` |
| `list` | 箇条（困りごと・要点） | 各項目の `id` |
| `compare` | 2〜4 案の比較カード | カードの `id`、点は `カード.1` `カード.2`…（または点の `id`） |
| `table` | 表 | 行の `id`（行の全セル）、列の `id`（列の全セル）、セル `行.列`、見出し `header` |
| `sequence` | シーケンス図 | 参加者の `id`、メッセージの `id`（省くと `m1` `m2`…） |
| `graph` | 箱と矢印（構成・業務の流れ・状態遷移） | ノードの `id`、辺 `出発>到着`（または辺の `id`）、グループの `id` |
| `swimlane` | スイムレーン（担当ごとの業務の流れ） | 担当の `id`（帯）、手順の `id`、辺 `出発>到着` |
| `beforeafter` | As-Is / To-Be（左右の手順を比べる） | `before` `after`（板）、各手順の `id`、`arrow`、手順の間の矢印 `前>後` |
| `roadmap` | ロードマップ（期間 × 流れ） | 期間の `id`、流れの `id`、項目の `id`、矢印の `from>to`、`grid`（見出しと区切り線と流れの帯）、`now` |
| `tree` | ツリー（論点・ロジックツリー・組織図） | ノードの `id`、枝 `親>子` |
| `chart` | 棒グラフ・折れ線 | 系列の `id`（系列の全部）、値 `系列.区分`、区分の `id`（その区分の全系列）、`axis` `categories` `legend` |
| `kpi` | 大きな数字のカード（出すと数え上がる） | カードの `id`、増減 `カード.delta` |
| `matrix` | 2×2 マトリクス | 象限の `id`（既定は `tl` `tr` `bl` `br`）、点の `id`、`axes` `quadrants` |
| `pyramid` | ピラミッド・ファネル | 段の `id`、ファネルの率 `段.rate` |
| `cycle` | サイクル（PDCA など） | 段階の `id`、弧 `前>次`、`center` |
| `venn` | ベン図（重なりと包含） | 集合の `id`、重なりの `id` |
| `canvas` | 下の層。座標で図形を置く（6 章） | 図形の `id` |
| `text` | テキスト（見出し・段落・箇条・囲み。8 章） | ブロックの `id`、箇条の項目 `ブロック.1` `ブロック.2`… |
| `image` | 画像・イラスト（8 章） | `img` |
| `frame` | 部品をまとめる枠（8 章） | `box` `title` |
| `space` | 3D の空間（8 章） | 要素の `id`、板（`plate`）の `id`。板の中の要素は `板の id/要素の id` |

図の `title` は章の題（画面の左上）になる。場面に `title` があればそちらが章の題になり、図の題は図の上に小さく出る。

### title

```json
{ "type": "title", "text": "経費の申請は、誰の手を通って\n経理に届くのでしょうか", "sub": "金額で変わる承認ルート" }
```

```json
{ "type": "title", "text": "動画作成プラグイン ugoku-zukai について\n説明します", "sub": "資料を渡してから動画のページができるまで" }
```

`sub` は任意。題に足す情報があるときだけ書き、題をなぞるだけなら付けない（章扉は題だけでよい。まとめの章扉は「まとめ」）。

テーマに `chapter`（章扉の色）があれば、`title` 図だけの場面は暗い地（章扉の地）で出る。同梱のテーマ `koo` では Navy の地に白い文字になる。通常の地に出したいときは、図に `"tone": "light"` と書く。`title` 図を他の図と並べる場面では、`"tone": "light"` が要る。

### toc

目次。見出し（既定は「目次」）の下に、章の番号と題を左揃えで並べる。目次やアジェンダを `title` 図や `custom` で作らずに、これを使う。

```json
{ "type": "toc", "items": [
  { "id": "c1", "text": "UX とは" },
  { "id": "c2", "text": "ユーザビリティとの違い" },
  { "id": "c3", "text": "UX 設計とは" } ] }
```

```json
{ "type": "toc", "items": [ … ], "current": "c2" }
```

- `items` の `id` は構成メモの章の id、`text` は章の題にする。`check_storyboard.cjs --outline` は、章の id・題・順が構成メモと違えば警告する（構成メモを直したら、目次も直す）
- `current`（任意）に章の id を書くと、その章を強調し、ほかの章を控えめにする。章の頭で同じ目次を出し直して、今どこにいるかを見せるときに使う
- `heading`（任意）は見出しの文字。`""` なら見出しを出さない
- 場面の頭で、全部の章が自動で出る（`show` は要らない）。項目の id で `focus` などを指せる
- 地は `title` 図と同じ。テーマに `chapter` があれば章扉の地で出て、`"tone": "light"` で通常の地になる。他の図と並べるときやスライドの部品にするときは `"tone": "light"` が要る

### list

```json
{ "type": "list", "title": "いまの困りごと", "numbered": true,
  "items": [ { "id": "i1", "text": "紙の領収書を毎月まとめて提出している", "sub": "月末に経理の作業が集中する" } ] }
```

8 個を超えると、検査が「画面で読み切れない」と警告する。

### compare

```json
{ "type": "compare", "title": "二つの案", "items": [
  { "id": "a", "label": "A案 クラウドの精算サービス", "role": "actor",
    "points": [ { "text": "スマホで撮って申請", "kind": "pro" }, { "text": "月額の費用", "kind": "con" } ] } ] }
```

`kind` は `pro`（✓）・`con`（✗）・`plain`（・）。

### table

```json
{ "type": "table", "title": "困りごとへの効き方",
  "columns": [ { "id": "issue", "label": "困りごと" }, { "id": "a", "label": "A案" } ],
  "rows": [ { "id": "r1", "cells": ["紙の提出", { "text": "なくなる", "mark": "check" }] } ] }
```

セルは文字か `{ "text", "mark": "check" | "cross" | "question" }`。`mark` は行が出るときに一緒に出る。後から付けるなら動作の `mark` を使う。`cells` は列の順の配列か、`{ 列id: 値 }`。

### sequence

```json
{ "type": "sequence", "participants": [ { "id": "staff", "label": "社員", "role": "actor" } ],
  "messages": [ { "id": "m1", "from": "staff", "to": "app", "label": "出勤を打刻" },
                { "id": "m4", "from": "kintai", "to": "app", "label": "受け付けた", "reply": true } ] }
```

メッセージは宣言の順に上から 1 段ずつ並ぶ。`from` と `to` が同じなら自分への矢印。`reply: true` は破線の戻り。

### graph

```json
{ "type": "graph", "direction": "right",
  "nodes": [ { "id": "sys", "label": "入力チェック", "role": "process", "sub": "金額・領収書", "shape": "box" } ],
  "groups": [ { "id": "approvers", "label": "承認者", "members": ["kacho", "bucho"], "style": "frame" } ],
  "edges": [ { "from": "app", "to": "sys", "label": "申請を送る", "style": "solid" } ] }
```

- `role`（色）: `actor` `process` `store` `external` `muted` `added` `removed`（と `good` `bad` `warn` `accent`）
- `shape`: `box`（既定）・`round`（状態遷移の角丸）・`store`（円筒。`role: "store"` の既定）
- `groups.style`: `frame`（囲む枠。既定）か `band`（層の帯。ブラウザ / API / データ のような区分）
- `direction`: `right`（既定）か `down`。省くと両方を試し、大きく描ける方を選ぶ
- `order`: `"declared"` と書くと、同じ段（`down` なら同じ行、`right` なら同じ列）の箱を `nodes` に書いた順に並べる。省くと、辺の交差が少なくなるように並べ替える（「コア 0〜3」が「3, 0, 1, 2」と並ぶことがある）。Morph でつながる系列では、どれかの図に書けば、1 枚のキャンバスを初めて出る図の順で組む
- 辺の `label` は具体的な動詞句（「公開鍵を取得」）。同じ向きの辺を 2 本引くときだけ `id` を書く
- 点は宣言した辺の上だけを通れる（`trace`）
- 多対多の関係（3 つ → 3 つなど）を `graph` で描くと、辺が増えて文字が小さくなる（`table` か `list` なら、辺なしで同じ関係を書ける）

**箱の中身 `inside`**（`/6`）: ノードに `"inside": "<figures の図の id>"` を書くと、その箱に `zoom` で寄ったとき、箱の名前が薄れて中身の図が現れる（意味のズーム。VG-17）。

```json
"system": { "type": "graph", "nodes": [
  { "id": "user", "label": "利用者", "role": "actor" },
  { "id": "server", "label": "注文サーバー", "role": "process", "inside": "server-inside" } ],
  "edges": [ { "from": "user", "to": "server", "label": "注文する" } ] },
"server-inside": { "type": "graph", "nodes": [ { "id": "web", "label": "Web" }, { "id": "db", "label": "注文 DB", "role": "store", "inside": "db-inside" } ],
  "edges": [ { "from": "web", "to": "db", "label": "書く" } ] }
```

- 書けるのは、スライドに置いた `graph` の箱だけ。Morph でつながる系列では、同じ id の箱どうしなら同じ中身を書ける。板（`plate`）に置いた `graph` の箱と、`space` の `box` に書くと誤りになる。`venn` の集合の `inside`（2 章の `venn`）は包含を表す別の書き方
- 中身は `figures` の図（`space`・`custom`・`title`・`frame`・`toc` は中身にできない）。1 つの図を中身にできる箱は 1 つ。中身の図は、部品や場面の図、板（`plate`）の図としては置かない
- 入れ子は 3 段まで。循環すると誤り
- 寄る: `{"zoom": "server"}`。中身の見え方はカメラの倍率で決まり（寄り切ると中身だけが見える）、時刻では決まらないので、シークしても同じ絵になる。倍率の上限は、`inside` の箱へは中身が読める倍率まで上がる（1 段ごとに 6 倍まで）
- 中に入ると、外の段は「外」になる: 中身が現れるのと同じ割合で、寄せ先の箱（と、それを含む外側の箱）以外の同じ段の要素（箱・矢印・矢印の `label`）と、同じスライドのほかの部品が薄れ、寄り切ると消える。寄せ先の隣の箱が本文の端で切れて見えることはない。中身の中の要素に寄るときの「端で切れる」の検査も、消える外の段は数えない
- 戻る: 外側の箱に `zoom` すると、その段に戻る。`{"zoom": "all"}` でスライドの写し方に戻る。スライドが変わっても戻る
- 中身の要素は、寄った後で `show`・`focus`・`trace` などの対象になる。id は `中身の図の id/要素の id`（一意なら要素の id だけでよい）。中身の中の `focus` は、中身の図だけを薄くする
- 箱を `show` すると、中身の図も出たことになる（見えるのは寄ったときだけ）
- 寄る前の箱は、後ろに縁を重ねた形で「中がある」とだけ示す（中身の文字は描かない）。スライドの完成形のコマは寄らない姿で、寄った姿は行ごとのコマに出る
- 中身の図は、寄り切ったときの箱の内側の大きさを区画にして、自然な大きさ（拡大しない）で組む。箱が小さいと、寄った後も中身が小さい。寄った後に中身が自然な大きさの 0.9 倍に届かない、本文に収まらないときは、検査が警告する
- 中身は、箱の `move`・`resize` には付いていかない

### 提案資料の図（M1b）

`trace`（点がたどる）と `reply` は、`graph` のほか `swimlane` `tree` `cycle` `roadmap` のマイルストーン・`chart` の折れ線の点など、箱のある図で使える。`axis` `grid` のようなまとめの id は、`show` で一度に出すためのもの。

#### swimlane

```json
{ "type": "swimlane", "lanes": [ { "id": "ninushi", "label": "荷主", "role": "external" } ],
  "steps": [ { "id": "irai", "lane": "ninushi", "label": "電話・FAXで依頼", "sub": "（任意）" } ],
  "edges": [ { "from": "irai", "to": "memo", "label": "（任意）" } ] }
```

列は辺から自動で決まる。隣の担当への受け渡しは同じ列で縦に、同じ担当の次の手順は右の列に置く（`col` で固定もできる）。左へ戻る辺は下を回る。担当は 5 本まで。

#### beforeafter

```json
{ "type": "beforeafter", "arrow": "受付を一つに",
  "before": { "label": "いま", "steps": [ { "id": "b1", "text": "紙から表計算に転記", "mark": "cross" } ] },
  "after":  { "label": "これから", "steps": [ { "id": "a1", "text": "荷主が Web で依頼" } ] } }
```

手順は上から下へ矢印でつながる（`"flow": false` なら箇条）。各側 6 個を超えると検査が警告する。板の色は既定で `before` = `muted`、`after` = `added`（`role` で変える）。構成図どうしを比べるなら、`graph` を 2 つ並べた場面にする。

#### roadmap

```json
{ "type": "roadmap", "periods": [ { "id": "q1", "label": "4〜6月" } ],
  "tracks": [ { "id": "sys", "label": "仕組み" } ],
  "items": [ { "id": "web", "track": "sys", "from": "q1", "to": "q2", "label": "Web の依頼画面" },
             { "id": "go", "track": "sys", "at": "q4", "pos": 0.75, "label": "FAX 終了" } ],
  "links": [ { "from": "web", "to": "go", "label": "（任意）" } ],
  "now": { "period": "q1", "pos": 0.1, "label": "いま" } }
```

`from`〜`to` は帯（出すと左から伸びる）、`at` はマイルストーン（ひし形。`pos` は期間の中の位置 0〜1）。同じ流れで期間が重なる帯は下の段へずれる。

`links` は項目から項目への矢印（id は `from>to`）。右の期間にある項目へは横向きに、期間が重なる項目（別の段・別の流れ）へは縦向きに引く。右から左へは引けない。最後の段階から次の工程へ渡すことを見せるときは、次の工程を項目として右の期間に置き、そこへ矢印を引く。図全体を `show` すると矢印も出る。項目を 1 つずつ出すときは、矢印も `{"show": "web>go"}` で出す。

#### tree

```json
{ "type": "tree", "direction": "right", "root": { "id": "chien", "label": "遅配が月 40 件", "children": [
  { "id": "shuppatsu", "label": "出発が遅れる", "edge": "（任意: 枝の言葉）", "children": [ { "id": "tenki", "label": "転記の待ち", "sub": "平均 25 分" } ] } ] } }
```

`direction` は `right`（論点・ロジックツリー）か `down`（組織図）。省くと大きく描ける方。5 段まで。図全体の `show` は根から 1 段ずつ（枝 → 子）。

#### chart

```json
{ "type": "chart", "kind": "bar", "unit": "件", "categories": ["4月", "5月"],
  "series": [ { "id": "shiken", "label": "試した営業所", "values": [38, 41], "role": "actor" } ] }
```

`kind` は `bar`（棒が下から伸びる）か `line`（線が引かれ、点に値）。区分の id は文字列そのもの（id に使えない文字があれば `c1` `c2`…。`{ "id", "label" }` でも書ける）。`min` `max` `decimals`、`"values": false`（値を出さない）。系列が 2 つ以上なら凡例が出る。

#### kpi

```json
{ "type": "kpi", "items": [ { "id": "k_time", "label": "受付 1 件の時間", "value": 4.5, "unit": "分", "decimals": 1,
  "delta": "-11 分", "better": "down", "prefix": "（任意: ¥ など）" } ] }
```

4 枚を超えると検査が警告する。`delta` の符号で ▲▼、`better`（`up` / `down`）と合わせて良し悪しの色になる。

#### matrix

```json
{ "type": "matrix", "x": { "label": "かかる手間", "low": "小さい", "high": "大きい" }, "y": { "label": "効き目" },
  "quadrants": { "tl": { "id": "sugu", "label": "すぐやる", "role": "accent" }, "br": { "id": "ato", "label": "後回し", "off": true } },
  "items": [ { "id": "p1", "label": "受付の一本化", "x": 0.42, "y": 0.82, "role": "actor", "size": 0.5 } ] }
```

点の `x` `y` は 0〜1（右・上ほど高い）。`size`（0〜1）で円の大きさ。点を動かすには `{"move": "p1", "to": {"x": 0.6, "y": 0.75}}`。

象限は塗り分けられる。当てはまる象限には `role`（役割の色を薄く敷く）、該当しない象限には `"off": true`（グレーで沈める）を書く。塗り分けると、どの象限が当てはまり、どれが当てはまらないかが色で読める。話の途中で塗るなら、宣言には書かずに `{"tint": "sugu", "as": "accent"}`、該当しないほうは `{"tint": "ato", "as": "off"}`。

#### pyramid

```json
{ "type": "pyramid", "kind": "funnel", "unit": " 社",
  "levels": [ { "id": "f1", "label": "案内した", "value": 120 }, { "id": "f2", "label": "登録した", "value": 84, "sub": "（任意）" } ] }
```

`levels` は上から。`kind` は `pyramid`（上が細い。土台から積むなら下の段から `show`）か `funnel`（上が太い）。ファネルで `value` があれば、段の間に前の段からの率（`段.rate`）が出る。6 段まで。

#### cycle

```json
{ "type": "cycle", "center": "毎月 1 回", "steps": [ { "id": "atsume", "label": "数字を集める", "sub": "（任意）", "edge": "（任意: 次への弧の言葉）" } ] }
```

3〜8 個（範囲の外は検査の誤り）を時計回りに並べ、最後から最初へも弧を引く（`"closed": false` で引かない）。

#### venn

```json
{ "type": "venn", "sets": [ { "id": "genba", "label": "現場の勘", "sub": "（任意）" } ],
  "overlaps": [ { "id": "o1", "of": ["genba", "data"], "label": "改善の案" } ] }
```

重なり合う集合は 2〜3 個。`overlaps` の言葉は重なりの真ん中に置く（3 つの重なりは `of` に 3 つ）。

ある集合が別の集合に含まれるときは、含まれる側に `"inside": "<含む集合の id>"` を書く。含まれる集合は、含む集合の円の内側に小さく描かれる。

```json
{ "type": "venn", "sets": [ { "id": "ux", "label": "UX（体験全体）" }, { "id": "us", "label": "ユーザビリティ", "inside": "ux" } ] }
```

1 つの集合に含められるのは 2 つまで（並べて描く）。入れ子（A ⊃ B ⊃ C）も書ける。含む集合が 1 つだけの図でもよい（上の例）。重なり合う集合の片方に含めると、もう片方の円にかからない位置に描く。`overlaps` の `of` に、含まれる集合は書けない。

## 3. 場面と行（scenes / lines）

```json
{ "id": "s1", "figure": "flow", "title": "（任意）章の題", "chapter": "（任意）c2", "lines": [
  { "id": "l2", "text": "{a}申請者が送った申請は、{b}最初に入力チェックを通ります。",
    "read": "（任意）読み。印も同じ位置に置く",
    "source": ["src/expense/check.ts:42"],
    "do": [ { "at": "a", "trace": ["app", "sys"], "label": "申請書" }, { "at": "b", "pulse": "sys" } ] } ] }
```

- `slide` はスライドの id（8 章）。`slide` と `figure` は、どちらか 1 つを書く
- `figure` は図 1 つか、2 つの配列（左右に並べる。`split` で左の幅の割合、既定 0.56）
- 場面が変わると、次の場面で使わない図は消え、使い続ける図は新しい区画へ動く
- `text` は字幕。2 行（1 行およそ全角 38 字）に収まらなければ文を分ける
- `read` は読み（任意）。英字の語や読みの分かれる漢字を、意図した読みで読ませる。間を入れたい所には読点（、）を書く。読点の間は 1 つ約 0.6 秒ある。**規格番号のように 1 桁ずつ読ませる所は、中黒（・）で区切り、数字はカタカナで書く**（`ISO 9241-210` → `アイエスオー・キュウ・ニ・ヨン・イチ・ノ・ニヒャクジュウ`）。ひらがなで書くと、前の語に続く「は」が助詞と読まれることがある（`ゼット・はち` が「ゼット・ワチ」になった）。中黒は語を切るが、間は短い（約 0.1 秒）。読点で区切ると、読みは合うが、区切りの数だけ遅くなる。英字の略語にカタカナの語が続く所（「AIチャットボット」）は、1 つのまとまりで読まれて略語の音が弱まることがある。読みの一覧では見えないので、気になるときは略語の後を中黒で区切る（`エーアイ・チャットボット`）
- `chapter` は構成メモ（`outline.md`）の章の id。合意した章と台本の場面を結び、章ごとの検査と直しの単位になる。1 つの章に場面をいくつ書いてもよい。書くなら全場面に書く（`--outline` を付けて検査するときは全場面に要る）。再生ページとスライドコンテのチャプター一覧は、`chapter` が同じ続きの場面を 1 つの章にまとめ、構成メモの章の `title` を題にする（構成メモがないときは、今までどおり場面の題が変わるところで区切る。`title` 図の場面の題は札の文の 1 行目）
- `role` は使わなくなった（前に作った台本に残っていても、検査もプレーヤーも読み飛ばす）。新しく書く台本には書かない
- `source` は根拠（構成メモの `source` と同じ書き方）。文字列の配列で書く（1 つだけなら文字列でもよい。それ以外の形は `check_storyboard.cjs` が警告し、一覧に出ない）。評価役が照合し、再生ページのチャプター一覧で、行の根拠として吹き出しにも出る。読んだ人がたどれるように、`"src/expense/check.ts:42"`・`"PR #12"`・`"https://example.com/guide 「承認は 2 段まで」"` のように場所か引用まで書く

## 4. 文中の印と時刻

`text` の中の `{名前}`（英数字と `_`）が印。字幕には出ない。動作の `at` に印の名前を書くと、**その位置の語を話し始める瞬間**に動作が始まる。

- `at` を省いた動作は、同じ行の直前の動作が終わってから始まる（最初の動作は行の頭）
- `after: 0.3` で印から少し遅らせる。`dur` で長さを変える
- 時刻は音声の時刻表（`tts.py` が作る `timeline.json`）から決まる。`tts.py` は印までの文を別に解析して全文のモーラ列と照らし合わせ、印の直後の語が鳴り始める時刻を書く。時刻表がなければ文字数から見積もる（実際の声より ±20% ほどずれるので、合成の後に検査し直す）
- 印は語の頭に置く。語の途中（「最{a}初に」など）に置くと読みが変わり、時刻がずれる
- 動作が行の終わりを 1.2 秒以上はみ出すと警告（次の行の声に重なる）

## 5. 動作（do）の一覧

1 つの動作には動詞をちょうど 1 つ書く。値が主な対象で、ほかのキーは引数。対象は部品の id。場面に図が 2 つあって同じ id があるときは `図/id` と書く。図の id を書くと図全体になる。

| 動詞 | 例 | 意味 | 既定の長さ |
|---|---|---|---|
| `show` | `{"show": "flow"}` / `{"show": ["app", "app>sys"]}` | 出す。図全体なら宣言の順（ノード → 両端が出た辺）に。行・カード・枠は中身ごと | 0.7 秒＋0.22 秒ずつずらす |
| `hide` | `{"hide": ["dot:dot"]}` / `{"hide": "note:kacho"}` | 消す。点は `dot:<名前>`（`trace` の `dot`。省いたら `dot:dot`）、注記は `note:<id>`（`note` の `id`。省いたら対象の id）で指定する。どちらも出した後でだけ消せる。消した点は、次の `trace` で 1 つ目のノードにもう一度現れる | 0.5 |
| `focus` | `{"focus": ["sys", "kacho", "sys>kacho"]}` / `{"focus": "plot"}` | 対象以外を薄くする。要素を指すと同じ図の中を、部品（図）の id を指すと同じ場面のほかの部品を薄くする（指した部品はそのまま）。注記・点・戻りの矢印は薄くしない | 0.6 |
| `unfocus` | `{"unfocus": true}` | 薄くしたのを戻す | 0.6 |
| `blur` | `{"blur": ["u", "u1"]}` / `{"blur": "rel"}` | 対象以外をぼかす。`focus` と違い、場面の全部の図に及ぶ（対象のない図は全体がぼける）。図の id を書くと、その図だけを残す。注記・点・戻りの矢印はぼかさない | 0.6 |
| `unblur` | `{"unblur": true}` | ぼかしたのを戻す | 0.6 |
| `pulse` | `{"pulse": "sys"}` | 一瞬強調する | 0.8 |
| `mark` | `{"mark": "keiri", "as": "check"}` | 印を付ける。`as` は `check` `cross` `question`。付け直すと差し替わる | 0.5 |
| `unmark` | `{"unmark": "keiri"}` | 印を外す | 0.4 |
| `trace` | `{"trace": ["app", "sys", "kacho"], "label": "申請書", "dot": "dot"}` | 点が経路をたどる（箱と辺のある図）。1 つ目は点のいる所。点は、辺の上を動く間だけ見える（辺の始まりで現れ、終わりで消える）。箱にいる間は、点の代わりにその箱の枠が点の色で強調される。`label` は点の札。点が何を表すかを、最初の 1 回だけ 1 秒見せる。その 1 秒は、点は動かずに箱を強調し、札が消えてから動き出す（同じ言葉の札は、後の `trace` に書いても出ない。言葉を変えたら、もう一度だけ出る） | 区間数 × 2.0（札を見せるときは＋1.0） |
| `reply` | `{"reply": ["kacho", "sys", "app"], "label": "差し戻し", "as": "bad"}` | 戻りの矢印を、行きの辺のラベルと反対の側に引く。区間ごとに逆向きの辺の宣言が要る | 区間数 × 0.8＋0.4 |
| `note` | `{"note": "kacho", "text": "多くはここで終わる", "link": false}` | 対象の脇に注記を置く（`id` を書くと、同じ対象に別の注記を付けられ、`hide` でその id を指定できる。重ならない所を自動で選ぶ。`move` する前の位置で決まるので、動かす部品には付けない） | 0.6 |
| `badge` | `{"badge": "2 / 3"}` | 右上の札。`""` で消す | 0.5 |
| `relabel` | `{"relabel": "k2.after", "text": "半日"}` | 文字を書き換える | 0.6 |
| `tint` | `{"tint": "sys>bucho", "as": "warn"}` | 線や行の色を役割の色に変える | 0.6 |
| `move` | `{"move": "box1", "by": [0, -90]}` / `{"to": [x, y]}` / `{"to": "別のid"}` / `{"to": {"x": 0.6, "y": 0.7}}`（matrix） | 部品を動かす（図のローカル座標） | 1.0 |
| `resize` | `{"resize": "yoken", "to": {"w": 300, "h": 210}, "text": "top"}` / `{"scale": 1.5, "anchor": "left"}` | 箱の大きさを変える（下の説明） | 0.9 |
| `zoom` | `{"zoom": "db", "at": "b"}` / `{"zoom": ["cache", "db"], "pad": 20}` / `{"zoom": "plot", "region": {"x": [0.5, 1], "y": [0, 0.6]}}` / `{"zoom": "all"}` | 本文の領域を、対象に寄せる（下の説明）。配列なら、それらを囲む範囲に寄る。`region` で対象の中の一部に寄る。`"all"` でスライドの写し方に戻る | 1.0 |
| `pan` | `{"pan": "replica"}` / `{"pan": "plot", "region": {"x": [0, 0.5]}}` | 倍率を保ったまま、対象（`region` があれば、その中の一部）へ移る | 0.9 |
| `set` | `{"set": "a", "to": 2.2, "dur": 3, "ease": "linear"}` | 名前付きの値（`values`）を `to` まで動かす（`/5`。下の説明） | 1.0 |
| `custom` | `{"custom": "ring", "dur": 1.6}` | 下の層。場面の上に台本の `custom` の関数で自由に描く（6 章。値に連動する `custom` の部品とは別物） | 2.0 |

共通の引数: `at`（印）・`after`（秒）・`dur`（秒）。

`resize` は、四角と楕円の箱（`graph` のノード、`canvas` の `rect`・`ellipse` など）の大きさを、話の途中で変える。最初は他の箱と同じ大きさで見せ、中に別の箱を入れる行から大きくする、といった使い方をする。

- `to` は図のローカル座標での幅 `w`・高さ `h`（片方だけでもよい）。`scale` は今の大きさに対する倍率（数か `[横, 縦]`）。どちらかを書く
- `anchor` は動かさない点。既定は `center`（中心）。`left` `right` `top` `bottom` と、`top-left` などの角も書ける
- 文字は箱の中心に付いていく。`"text": "top"` と書くと、新しい箱の上に寄る（中に別の箱を入れるとき）
- 同じ箱にもう一度 `resize` を書くと、前の大きさから続く
- つながる矢印や隣の箱は動かない。大きくした箱が隣の箱にかかるか区画からはみ出すと、配置の検査が知らせる（中にすっぽり入る箱は構わない）。大きくした後の形は座標で決まるので、`canvas` で使うのが確実
- スライドの完成形のコマは、大きさを変えた後の形で出る

**`set`**（`/5`）: 名前付きの値を、`dur` 秒かけて `to` まで動かす。`ease` は `smooth`（既定。始めと終わりが緩やか）か `linear`（一定の速さ）。動いている間の値は、`custom` の部品の関数に毎コマ渡る。前の `set` が動いている途中で同じ値の `set` が始まると、その時点の値から動く。値は時刻だけで決まるので、シークしても同じ絵になる。名前が `values` にないと誤り。

**`show` の `"draw": true`**（`/4`）: 線を始点から伸ばして出す。線を描いてから（進みの 0〜0.7）、面（0.65〜1）と文字（0.7〜1）が出る。既定の長さは対象 1 つにつき 1.4 秒。箱の枠、実線・破線の辺、グループの枠、`frame` に効く。線のない要素に書くと、普通の `show` になり、検査が警告する（VG-12）。書かなければ、今までどおりの出方になる。

**カメラ（`zoom`・`pan`）**（`/4`）: 本文の領域だけを寄せる。見出し・言いたいこと・字幕・右上の札は動かず、本文からはみ出す部分は切り取られる。

- `pad` は寄せたときの周りの余白（画面の px、既定 40）。倍率は最大 2 倍（`inside` の箱へは、中身が読める倍率まで。2 章の `graph`）
- `space` の要素（8 章）にも寄れる。寄せる先は、寄り始めた時点の値で投影した外接矩形で、寄っている間に `yaw` が回っても追わない。このカメラは本文の 2D のカメラで、3D のカメラ（`yaw`・`pitch`・`scale`）とは別に動く
- `region` は、対象の画面上の矩形の中の一部を、割合（0〜1）の `{ "x": [始まり, 終わり], "y": [始まり, 終わり] }` で指す（片方を省くと 0〜1）。中の要素に id のない `custom` の部品で、グラフの一部に寄るときに使う。ほかの部品にも効く。`"all"` には付けられない
- 寄せる先は、もう出ている要素にする（まだ出ていない要素に寄せると、検査が「カメラ」の誤りにする）
- スライドが変わると、0.8 秒かけてそのスライドの写し方に戻る。同じスライドが続く場面の間は、寄ったまま引き継ぐ。図だけの場面では、場面が変わると戻る
- Morph でスライドが変わる場面に書いた `zoom`・`pan` は、`at` があっても Morph が終わってから動く
- 警告: 1 行の中でカメラが 3 回以上動く、倍率が 1 未満になる（`pad` が大きすぎる、区画いっぱいの部品の全体に寄る、など。部品の中の一部に寄るなら `region` で指す）、寄せた先が本文に収まらない
- スライドの完成形のコマにはカメラが掛からない。行ごとのコマは、寄せた後の絵になる（VG-11）

`show` と `hide` には `stagger`（秒）も書ける。対象が 2 つ以上のときに、1 つずつ出す（消す）間隔で、既定は 0.22。このとき `dur` は対象 1 つぶんの長さ（既定は `show` 0.7、`hide` 0.5）で、動作全体の長さは `dur` ＋ `stagger` ×（対象の数 − 1）になる。図の id を `show` すると、対象は図の部品すべてになる（部品の数は図の種類で違い、表では行の数より多い）。そのため `stagger` を少し増やすだけで全体が長くなる。行の声より長くなると、検査が「動きが行の終わりよりはみ出す」と警告する。

## 6. 下の層（canvas・move・custom の動作）

語彙で表せない絵だけに使う。値に連動して描く `custom` の部品（`"type": "custom"`）は下の層ではなく、スライドの部品の 1 つである（8 章の「custom（値に連動して描く部品）」）。使ったら、評価役が意図を読めるよう行の `source` か `note` で何を描いたかを書く。

**canvas**: 1184 × 470 のローカル座標に図形を置く（`width` `height` で変えられる）。

```json
{ "type": "canvas", "shapes": [
  { "id": "box1", "shape": "rect", "x": 160, "y": 170, "w": 220, "h": 110, "role": "actor", "text": "紙の領収書" },
  { "id": "e1", "shape": "ellipse", "x": 800, "y": 160, "w": 240, "h": 130, "role": "added", "text": "写真のデータ" },
  { "id": "arr", "shape": "arrow", "points": [[390, 225], [790, 225]], "text": "スマホで撮る", "dashed": false },
  { "id": "cap", "shape": "text", "x": 592, "y": 380, "text": "説明", "size": 22, "anchor": "middle", "bold": false } ] }
```

`shape` は `rect` `ellipse` `line` `arrow` `text`。`text` に `"over": ["図形の id"]` と書くと、その図形の上に重ねてよい文字になる（円の中に置く名前など。配置の検査が「箱に重なる」と言わない）。ほかの動詞（show / focus / move …）はそのまま使える。

**custom の動作**（前からある形）: 動作の `{"custom": "ring"}` は、場面の上に、場面の間だけ表示される自由描画。関数の引数は `{ g, p, t, el, S, UZ, area }`（`g` は毎コマ空にされる SVG の g、`p` は 0〜1 の進み、`el(tag, attrs, parent)` で要素を作る、`S` はテーマの色、`area` は図の区画）。配置の検査はこの中を見ないので、画面で確かめる。新しく書くなら、値に連動し、検査が中を描いて見る `custom` の部品（8 章）を使う。

## 7. 検査が見ること

`check_storyboard.cjs` はプレーヤーと同じ JS で配置を計算し、各行の終わりと各動作の終わりのコマを調べる。

- 形: 必須の項目、id の重複・使えない文字、図の種類ごとの宣言（辺の両端がノードにあるか、セルの数など）
- 解決: 動作の対象が場面の図にあるか、印が文にあるか、点の経路が宣言した辺か、点がいまいる所から書いているか
- スライド: 部品の id の重複、区画の範囲、完成形で区画が重なる部品（`transient` とフレームは除く）、言いたいことが 2 行に収まらない（警告）、画像のファイルが読めない、画像に出どころ（`source`）がない（警告）
- 配置: テキストの部品が区画に収まらない、区画からのはみ出し、文字が 15px 未満に縮んでいないか、文字どうしの重なり、ラベルや注記が別の箱や枠の縁に重なっていないか
- `/4` の表現: `morph` の指す先（直前のスライドにある、同じ `type` の図か）、Morph で要素がつながらない場合（自動の連番 id。対象外の図の種類）の警告、カメラの警告（1 行に 3 回以上・倍率 1 未満・本文に収まらない）とまだ出ていない要素への zoom（誤り）、線のない要素への `draw`（警告）、`/3` 以前の台本で使ったとき（誤り）
- `/5` の表現: `values` の形（名前と数）、`set` の名前が `values` にあるか・`to`・`dur`・`ease`、`custom` の部品の `draw` が台本の `custom` にあるか。`custom` の部品は node で実際に描き、関数が例外を投げる、TeX の誤り、`/4` 以前の台本で使ったときは誤り。属性に `NaN`・`Infinity` が入る、描いたものが部品の区画からはみ出すときは警告
- `/6` の表現: `space` の宣言（`kind` ごとの必須の項目、点の形、式の中の名前、`camera`・`axes`・`bounds` の形）、板の `figure`・`fill`・`label`・`labelWidth`、板の id の重なり、`inside`（`graph` の箱だけ、中身の図があるか、1 つの図を 2 つの箱に使っていないか、入れ子 3 段まで、循環）、`/5` 以前の台本で使ったとき（誤り）。`space` の部品は node で実際に投影し、描けない（式の例外、プリミティブが 6000 を超える）、見えている要素が丸ごと数にならないときは誤り。はみ出し、面が交差して前後が決まらない、板が傾きすぎて読めない、板の中の文字が小さい、`space` の要素への `trace`、寄った後の中身が小さい・本文に収まらないときは警告
- 構成メモ（`--outline` を付けたとき）: 場面の `chapter` がない・構成メモの章にないものは誤り。まだ場面のない章、章の順の違い、章ごとの見積もりの長さが尺の目安から 30% を超えてずれているものは警告。`--complete` を付けると、場面のない章は誤りになり、台本全体の長さも構成メモの長さと比べる（15% を超えると警告）
- 警告: 使っていない印、字幕が 2 行に収まらない、show していない図、行の終わりをはみ出す動き、`graph` の辺に label がない（警告では終了コードは 0。辺の label は、意図して省いたのでなければ付ける。成功基準 G-M2）

## 8. スライド（slides）

スライドは 1280×720 の 1 枚。上から、見出し（`title`）、言いたいこと（`statement`）、本文の領域に並べた部品（`parts`）でできている。`slides` に id を付けて宣言し、場面から `slide` で指す。続く場面が同じスライドを指すと、出した部品はそのまま残る。別のスライドを挟んで戻っても同じ。

```json
"slides": {
  "definitions": {
    "title": "二つの言葉の定義",
    "statement": "ユーザビリティは使いやすさ、UX は体験の全体を指します。",
    "start": "complete",
    "parts": [
      { "figure": "rel", "area": { "col": [1, 4], "row": [1, 6] } },
      { "id": "defs", "type": "text", "area": { "col": [5, 12], "row": [1, 6] }, "blocks": [
        { "id": "u", "kind": "heading", "text": "ユーザビリティ" },
        { "id": "u1", "kind": "para", "text": "目標を**有効に、効率よく、満足して**達成できる度合い。", "source": ["ISO 9241-11:2018 3.1.1"] } ] }
    ]
  }
}
```

- `title`（必須）: スライドの見出し。字幕の言い回しに合わせず、資料の見出しとして書く
- `statement`（任意）: この 1 枚で伝えたいことの 1 文。見出しの下に出る。2 行まで。多くのスライドに付けるが、図だけで足りる 1 枚には要らない
- `tone`（任意）: `"dark"` と書くと、地を章扉の色（同梱の `koo` では Navy）にする。見出し・言いたいこと・テキストの部品の文字は白、強調はテーマの `chapter.accent`（`koo` では Blue #5090d9）、図の線と補足の文字も暗い地の色になる。箱の面は明るいまま。目次や区切りの 1 枚など、地を変えて目立たせたいときに使う。部品の色は、その部品が最初に出るスライドの地で決まる（同じ図を明るい地と暗い地の両方に置かない）。テーマに `chapter` がなければ通常の地
- `start`（任意）: `"complete"` と書くと、最初に使う場面の頭で、部品がすべて出る（完成形から始め、`focus` や `blur` で順に説明する）。省くと、見出しと言いたいことだけが出た状態から、行の動作（`show`）で部品を出していく
- `parts`: 部品の列。台本に書いた順に重ねて描く
  - その場で宣言する: `id` と `type` を持つ図の宣言（2 章の図と、下の `text` `image` `frame` `custom` `space`）
  - `figures` の図を指す: `{ "figure": "図の id" }`。同じ図を、いくつものスライドに置ける
  - 部品の id は図の id と同じ扱いで、台本全体で 1 つ。動作の対象は今までどおり部品の中の id（同じ id があるときは `部品/id`）
  - `area`: 部品を置く区画。本文の領域を 12 列 × 6 行に分け、`col` と `row` に「始まり, 終わり」（1 始まり、両端を含む）を書く。部品が 1 つだけなら省ける（全面）
  - `transient: true`: 完成形に含めない部品（途中で消して、同じ区画の別の部品に入れ替えるもの）。`start: "complete"` でも自動では出ない
  - `valign`（`top` / `middle` / `bottom`）・`halign`（`start` / `center` / `end`）: 部品が区画より小さいときの、区画の中での位置。既定は、テキストは上、ほかは中央。並べた部品の上下をそろえたいときや、空きを 1 か所に寄せたいときに書く
  - `fit: "content"`: 区画に合わせて組まない（下を参照）。図は最初に出る場面で 1 回だけ組むので、`fit` はそこで決まる（`valign`・`halign` は部品ごとに変えられる）
  - `morph`（`/4`）: 直前のスライドの図の id。この部品を、その図から変形して出す（下の「Morph」）
- 表（`table`）・箇条（`list`）・循環図（`cycle`）は、スライドでは**区画に合わせて組む**。文字を最大 1.3 倍まで大きくし（折り返しが増えない範囲で）、区画の幅いっぱいに広げ、余った高さを行や項目の間に配る（配りきれない分は空きになり、`valign` で寄せる）。循環図は、横に広い区画では横長の輪になる。中身の量に合った大きさのままにしたいときは、部品に `fit: "content"` と書く。ほかの図は、今までどおり区画に収まる大きさまで伸び縮みする
- スライドでは、図の `title` は図の上に出ない（見出しとテキストの部品がその役をする）

**完成形**は、`transient` でない部品がすべて出た状態を指す。`relabel` や `mark` で変えた後の見た目、注記、点は含まない。`frames.cjs` が、スライドごとに完成形のコマ（`svg/slide-<id>.svg` と、それを PNG にした `slide-<id>.png`）を書く。完成形で区画が重なる部品があると、検査が誤りにする（フレームは除く）。

スライドの形の例（`examples/slide-forms.json`）: 言いたいこと＋図／言いたいこと＋図と文章を左右に／言いたいこと＋定義の囲みと小さな図／画像と、枠に入れた箇条。型ではないので、区画は内容に合わせて決める。

### Morph（スライドをまたいで図をつなぐ。`/4`）

後のスライドの部品に `"morph": "<前の図の id>"` を書くと、スライドが変わるときに 0.8 秒で前の図から変形する。同じものが育つ・前と後が続く、という見せ方ができる（VG-10）。Morph はスライドの並びで成り立つので、スライドを切るときに考える。

```json
"arch-v1": { "title": "最初の構成", "parts": [ { "figure": "v1" } ] },
"arch-v2": { "title": "キャッシュを足した構成", "parts": [ { "figure": "v2", "morph": "v1", "area": { "col": [1, 12], "row": [1, 4] } } ] }
```

- 誤りになるもの: 指す図が、この部品を最初に使う場面の直前のスライドにない、`type` が違う、同じスライドに前の図も置いている、つながりが枝分かれ・循環・逆順になる
- 要素は、書いた id が同じものどうしでつながる。`graph` のエッジ（`A>B`）のように id から決まるものもつながる。自動で振られる連番の id（id を書いていない `compare` の項目など）はつながらず、「Morph でつなぐなら id を書く」と警告が出る
- `graph`: Morph でつながる図の列（v1 → v2 → v3 …）を、全部の要素を合わせた 1 枚のキャンバスに配置する（先のスライドの要素から順に並べるので、後から加わる箱はなるべく外側に入る。必ずではない）。共通のノードは動かず、各スライドは自分の図の部分を区画に写す（v1 は v1 の部分に寄って大きく出る）。切り替えでは写す範囲が広がり、増えた要素は空いていた場所に現れる。後の図で置き換わる辺は、図ごとに引き直す。段階ごとにノードの id を変えない
- `list`・`compare`・`table`: 同じ id の項目・行が、位置を補間して滑る。大きさが補間されるのは `compare` のカードの箱だけで、`list` の項目と `table` の行・セルの文字と行の矩形は、最初のコマで後の大きさに切り替わる。前後で区画の大きさが同じなら、文字の大きさも変わらず、滑らかに読める
- そのほかの図の種類: 要素はつながらず、前の図が消えて次の図が出る（警告が出る）
- 引き継ぐのは「出ているか」だけ。強調・印・注記は引き継がない。新しく増えた要素は、スライドの `start` に従って出る（省いたら `show` で出す）
- 補間の途中はコマに出ない。完成形のコマは、それぞれのスライドの図の完成形になる
- `alts.py` の案で、Morph の前後どちらかのスライドを置き換えると、`morph` の検査で止まる。Morph と案は組み合わせられない

### text（テキスト）

```json
{ "id": "defs", "type": "text", "blocks": [
  { "id": "h", "kind": "heading", "text": "小見出し" },
  { "id": "p", "kind": "para", "text": "段落の文。**強調する語**。" },
  { "id": "b", "kind": "bullets", "items": ["一つ目", "二つ目"] },
  { "id": "q", "kind": "quote", "text": "定義や引用の文。", "source": ["ISO 9241-210:2019 3.15"] } ] }
```

- `kind`: `heading`（小見出し）/ `para`（段落）/ `bullets`（箇条。項目の id は `b.1` `b.2`…。`b` は全項目）/ `quote`（定義や引用の囲み。`source` が囲みの下に出る）
- 文字の大きさの既定（1280×720 の画面の px）: 段落と箇条 24、小見出し 26、引用 28。利用者が大きさを望んだときは、ブロックに `size`（15〜60 の数）を書いて変える
- `**語**` で語を強調する（太字と強調色）
- `source` は出どころ（行の `source` と同じ書き方）。事実を書いたブロックに付ける。評価役が照合する
- 幅は区画いっぱいで、区画の上に寄せる。文字は拡大も縮小もしない。区画に収まらないと、検査が「テキストが区画に収まらない」と知らせる（文を減らすか、区画を広げる）
- 書き言葉で書く。`check_text.py` は禁止語だけを見る（読みや語尾の規則はかけない）

### image（画像・イラスト）

```json
{ "id": "person", "type": "image", "src": "assets/person.svg", "alt": "利用者", "source": "同梱（自作）", "license": "…", "credit": "…" }
```

- `src`: 台本のあるフォルダからの相対パス。PNG・JPEG・SVG。フォルダの外は指せない
- 縦横比を保って、区画に収まる最大の大きさで出る
- `source`: 出どころ（どこから取ったか。利用者から渡されたものなら、そう書く）。ないと検査が警告する。`license` に利用条件、`credit` にクレジットの文を書く。`credit` は、終わりの札の「音声: …」の下に出る
- 画像は、再生ページの中に埋め込まれる。ページが 15MB を超えると `build_player.py` が止まるので、大きな画像は先に小さくする

### frame（フレーム）

```json
{ "id": "box", "type": "frame", "title": "利用者が体験すること", "area": { "col": [5, 12], "row": [1, 6] } }
```

区画いっぱいの囲み。他の部品と区画が重なってよい。中に入れる部品より**前**に書く。フレームの区画の中にある部品は、枠の内側に余白を取って置かれる（題があれば、その下から）。

### custom（値に連動して描く部品。`/5`）

座標・グラフ・接線・面積・ベクトル・数式を、名前付きの値に連動して描く部品。下の層の `custom` の動作（6 章）とは別物である。スライドの部品か `figures` の図として宣言し、関数は台本の最上位の `custom` に名前を付けて文字列で書く。

```json
"values": { "a": -2.4 },
"custom": { "tangent": "({ g, v, geo, w, h }) => { … }" },
"slides": { "tangent-slope": { "title": "接線の傾き", "parts": [ { "id": "tan", "type": "custom", "draw": "tangent", "area": { "col": [1, 12], "row": [1, 6] } } ] } }
```

- `draw` は台本の `custom` の関数の名前。関数は毎コマ `{ g, v, t, el, S, UZ, geo, w, h }` を受け取り、部品のローカル座標（0〜`w` × 0〜`h`）で `g` に描く。`v` は名前付きの値、`geo` は幾何の道具。引数・道具・TeX の数式・リファレンスは `geometry.md`
- 部品は区画いっぱいの描き場で、伸び縮みしない。`w`・`h` はそのときの区画の大きさ（画面の px）で、区画が変わるスライドでは新しい `w`・`h` で描き直される（文字の大きさと縦横比が保たれる）。スライドが変わって区画が動く 0.8 秒の間は、`w`・`h` も補間して毎コマ描く。関数の中で `w`・`h` に合わせて配置しておけば、全面から上半分へ移しても崩れない
- ほかの部品と同じく `show`・`hide`・`focus`・`blur`・`zoom`・`pan` が効く。中の要素は id を持たないので、対象にするのは部品全体である。部品の中の一部に寄るには、`zoom`・`pan` の `region`（部品の区画に対する割合）を使う。部品の id を `focus` すると、同じ場面のほかの部品が薄くなる（5 章）
- スライドの完成形のコマは、そのスライドを使う最後の場面の終わりの値で描く
- 同じ部品を続くスライドで使い続けるには、`figures` に宣言して、各スライドから `{ "figure": "<id>" }` で指す（スライドの中で宣言した部品の id は、ほかのスライドで繰り返せない）
- 検査は、各行の終わりと各 `set` の途中・終わりのコマで関数を実際に描く（7 章）

### space（3D の空間。`/6`）

点・線・矢印・多角形・直方体・曲面・曲線・文字・板を 3 次元の座標で置き、カメラで写す部品。カメラの向きや要素の座標を名前付きの値にすると、`set` で回り込んだり要素を動かしたりできる（VG-15・VG-16）。スライドの部品か `figures` の図として宣言する。

```json
{ "id": "sp", "type": "space",
  "camera": { "yaw": "yaw", "pitch": 25, "scale": 85, "target": [0, 0, 1] },
  "axes": { "x": [-2, 2], "y": [-2, 2], "z": [0, 3], "labels": { "x": "x", "y": "y", "z": "z" } },
  "items": [
    { "id": "dome", "kind": "surface", "f": "3 - (x*x + y*y)/4", "x": [-2, 2], "y": [-2, 2], "grid": 32, "color": "s1", "color2": "s3" },
    { "id": "P", "kind": "point", "at": ["a", 0, "3 - a*a/4"], "label": "P" },
    { "id": "v", "kind": "arrow", "from": [0, 0, 0], "to": [1, 1, 2], "color": "s2" },
    { "id": "c", "kind": "curve", "fn": ["cos(t)", "sin(t)", "t/4"], "t": [0, 6.28] },
    { "id": "top", "kind": "text", "at": [0, 0, 3.2], "text": "最大" } ] }
```

- 座標は右手系で、z が上。`yaw: 0, pitch: 0` で、x が右、y が奥、z が上（真正面）になる。投影は平行投影で、遠くのものも小さくならない
- `camera`: `yaw`（鉛直軸まわりの角度。度）、`pitch`（見下ろす角度。度。0 は真横、−90〜90）、`scale`（ワールドの 1 単位を何 px で描くか。省くと範囲が区画に収まる大きさ）、`target`（注視点。省くと範囲の中心）。どれも数か、値の名前か、式で書ける
- 範囲: `axes` は軸と目盛りを描き、その範囲をカメラの範囲にする（`labels` で軸の名前）。軸を描かずに範囲だけを決めるときは `"bounds": { "min": [x, y, z], "max": [x, y, z] }`。どちらも書かないと、台本の初めの値（`values`）で要素を置いた範囲を使い、`set` で要素が動いても範囲は変わらない（全体が寄ったり縮んだりしない）
- 数を書く所（座標・範囲・カメラ・板の大きさと傾き）には、数、値の名前、値を含む式（`"a*2"`、`"3 - (a*a + b*b)/4"`）を書ける。式で使える関数は `sin` `cos` `tan` `sqrt` `abs` `exp` `log` `pow` `min` `max` と定数 `PI`。曲面の `f` では `x`・`y`、曲線の `fn` では `t` も使える。値の名前に関数の名前（`sin` など）は使えない

| `kind` | 書くこと | 補足 |
|---|---|---|
| `point` | `at` | `r`（半径）、`label` |
| `line` | `points`（2 つ以上の点）か `from`・`to` | `width`。`draw` で点の順に伸びる |
| `arrow` | `from`・`to` | `width`、`label`（矢の先） |
| `polygon` | `points`（3 つ以上の点） | `label` |
| `box` | `min`・`max`（対角の 2 点） | 直方体。`label`（上の面の中央） |
| `surface` | `f`（`z = f(x, y)` の式）、`x`・`y`（範囲） | `grid`（網目の分割。既定 24、上限 64）、`color2`（高さで `color` から `color2` へ色を変える） |
| `curve` | `fn`（`[x(t), y(t), z(t)]` の式）、`t`（範囲） | `n`（分割。既定 64、上限 512） |
| `text` | `at`、`text` | `tex: true` で TeX の数式 |
| `plate` | `figure`、`origin`、`size` | 下の「板」 |

- どの要素にも `color`（`geo` と同じ色の名前。見分けるための線の並び `s1`〜 が使える。`geometry.md` の 1 章）と `opacity`（0〜1）を書ける。`label` の色は `labelColor`
- 描き方: 面・線・点・文字を奥から順に塗る。面の明るさは面ごとに一様で、向きによって地の色の方へ少し寄る（色相は変わらない）。文字はいつも正面を向き、奥行きで大きさが変わらない。接する面どうし（曲面と接平面など）は、塗る順の都合で継ぎ目に筋が出ることがある。網目を細かくし、手前の面を少し浮かせると目立たなくなる（見本 `depth.json` の接平面は 0.05 浮かせた）
- 動作: 要素の `id` に `show`（`draw` で線と面の輪郭が伸びる）・`hide`・`focus`・`pulse`・`tint`・`zoom`・`pan` が効く。同じ id がほかの部品にもあれば `部品/要素の id` と書く。部品の id を `show` すると、全部の要素が出る。軸は、要素のどれかが出ると一緒に出る。`zoom`・`pan` は本文の 2D のカメラで、寄せる先は寄り始めた時点の値で投影した外接矩形（5 章）。`trace` は `space` の要素にはまだ効かない（検査が警告し、その動作は動かない）。`mark`・`note` の位置は、部品の区画の中央が基準になる
- 3D の Morph はない。同じ `space` の部品を続くスライドに置いて値を動かせば、カメラと要素は続いて見える（同じ部品を続くスライドで使うには `figures` に宣言する）
- 部品は区画いっぱいの描き場で、`custom` の部品と同じく区画の大きさで描き直す。スライドの完成形のコマは、そのスライドを使う最後の場面の終わりの値で描く
- 検査（7 章）は、各行の終わりと各 `set` の途中・終わりの値で実際に投影する
- 宣言で書けない立体（関数で決まる曲面、繰り返しで作る形など）は、`custom` の部品の中で `geo.space` を使って描ける（`geometry.md`）

**板（`plate`）**: 2D の図を、空間の中の長方形として置く。正面から見ると普通のスライドの部品と同じ絵で、板とカメラを値で動かすと起き上がる（VG-16）。

```json
{ "id": "service-layer", "kind": "plate", "figure": "services",
  "origin": [-5.6, 0, 2], "size": [11.8, 1.0], "tilt": "rise",
  "label": "処理", "labelWidth": 1.4, "fill": "muted", "opacity": 0.25 }
```

- `figure`: `figures` の図の id か、その場の図の宣言（`type` を持つオブジェクト）。`space` は板に置けない。板に置いた図を、同じスライドに部品としても置くと誤り
- `origin` は板の左上の角、`size` は `[幅, 高さ]`（ワールドの単位）。`tilt` は、板の上辺を軸に手前へ倒す角度（度。既定 0 で、板は xz 面に立って正面を向く。90 で水平になる）。どれも値の名前か式で書ける
- 中の図は、板の大きさに合わせて 1 回だけ組み、板の傾きと投影を行列 1 つで掛けて描く。文字は板と一緒に傾く（正面を向かない）。組み方は 8 章の部品と同じで、表（`table`）・箇条（`list`）・循環図（`cycle`）は板の幅いっぱいに広げて組み、ほかの図は縦横比を保ったまま板に収まる大きさまで伸び縮みする。カードの幅に上限のある比較（`compare`。カード 1 枚 460px まで）などは、横に長い板では左右が空き、幅の違う板を並べても中の図はほぼ同じ大きさになる。板の幅いっぱいに見せたいなら `table` で書く
- `fill`: 板の面を塗る色の名前（省くと面は描かず、図だけが浮く）。`opacity` は塗りに掛かる。`label`: 板の左端に置く名前（板と一緒に傾く）。`labelWidth`: 名前のために左に取る帯の幅（ワールドの単位。省くと名前の幅から決まる）。帯の幅をそろえると、板どうしで図の左端がそろう
- id: 板の id は台本全体で 1 つにし、図や部品の id と重ねない。中の図の要素は `板の id/要素の id`（一意なら要素の id だけでよい）で指す。板の id を `show` すると、中の図が全部出る（面と名前も）。板の中の要素に `focus` すると、ほかの板と空間の要素も薄くなる。板の中の要素に `zoom` すると、寄り始めの値で写した矩形に寄る
- 検査: 値が止まっている行の終わりで、板の面が視線に対して 70° を超えて傾いていると「傾きすぎて読めない」、写した中の文字が 15px 未満になると「文字が小さすぎて読めない」と警告する。中の図も、普通の図と同じ配置の検査（文字の重なりなど）を通る。板どうし・板と面の交差も警告する
- 平行投影なので、奥の層がゆっくり動く視差は出ない
